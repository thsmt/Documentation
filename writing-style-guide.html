基本ルール

項目ルール
説明文対象、理由、制約、実施方法が一読で分かる文章にする
CLIのみの操作AWSマネジメントコンソールでは実施できず、AWS CLIのみで変更可能な仕様を冒頭で明記する
コマンド原則として1つのコマンドにつき1つのコードブロックへ分ける
連続操作同じ対象の状態確認、設定、再確認などは1つのコードブロックへまとめてよい
利用者指定値置換値、選択値、リソース名、IAMロール名、IAMポリシー名をオレンジ色の等幅書体で表示する
固定識別子コマンド名、APIアクション、プロパティ名を通常色の等幅書体で表示する
出典説明文へ埋め込まず、対象説明の直下に独立した出典行を配置する
ℹ️ 情報 このページを新規ページ作成時の表示見本とし、詳細な文章ルールはCONTRIBUTING.mdで管理する

文章のまとめ方

手順の冒頭では、対象、制約、実施方法を一文で伝える。AWSマネジメントコンソールでは実施できず、AWS CLIのみで変更できる場合は、その仕様を明記する

避ける例

EC2起動後にEBSボリュームの設定を変更する場合は、AWS CLIでコマンドを実行する。追加EBSボリュームは終了時削除が無効になっている場合があるため確認する

良い例

EC2インスタンス起動後に追加したEBS終了設定（DeleteOnTermination）を変更する場合は、AWS CLIのみで変更可能

情報 良い例は、何を変更するのか、いつの設定なのか、なぜCLI手順を掲載するのかを一文で判断できる

コマンドブロック

変数代入、ユーザー作成、設定変更など、単独で意味を持つ操作は1つのコマンドにつき1つのコードブロックへ分ける

パスワードの対話入力

PowerShell
$Password = Read-Host "Password for <CUSTOMER_USER>" -AsSecureString

ローカルユーザーの作成

PowerShell
New-LocalUser -Name "<CUSTOMER_USER>" -Password $Password -Description "<CUSTOMER_USER>"

サービス状態の確認、設定、再確認のように、同じ対象へ連続して実行する短い操作は1つのコードブロックへまとめてよい

Postfixサービスの自動起動確認と有効化

bash
systemctl is-enabled postfix.service
systemctl enable postfix.service
systemctl is-enabled postfix.service
注意 複数コマンドをまとめる場合も、対象が同じで、上から順番に安全に実行でき、途中結果を読み取れることを条件とする

置換値を含むAWS CLI

利用者が置き換える値を<UPPER_SNAKE_CASE>形式で記載する。コードブロック内の置換値は自動的にオレンジ色で表示される

CloudShell
aws ec2 describe-instances --instance-ids <INSTANCE_ID> --region <REGION>

置換値を含まない通常のAWS CLI

利用者が変更する値を含まないコマンドは、通常色のコードブロックで表示する

CloudShell
aws sts get-caller-identity

複数の置換値を含むJSON

JSON内でもアカウントIDなどの置換値と、利用者が決定するリソース名をオレンジ色で表示する

json
{
  "ScheduleExpression": "<SCHEDULE_EXPRESSION>",
  "State": "ENABLED",
  "ActionAfterCompletion": "NONE",
  "RoleArn": "arn:aws:iam::<ACCOUNT_ID>:role/EventBridgeSchedulerEC2Stop"
}

置換値と固定値

利用者が入力または選択する値は、オレンジ色の等幅書体で表示する。コマンド名、APIアクション、設定プロパティなど変更しない識別子は、通常色の等幅書体で表示する

種類表示例用途
置換値<CUSTOMER_USER>実行前に利用者が置き換える値
選択値NONE画面または設定ファイルで利用者が指定する値
リソース名EventBridgeSchedulerEC2Stop環境ごとに決定するロール名やリソース名
固定識別子scheduler:GetWidget変更しないAPIアクションやプロパティ名

画面操作の記載例

Scheduleを有効化し、完了後のアクションはNONE、再試行はOFF、DLQはなし、暗号化はデフォルトとする。「既存のロールを使用」を選択し、EventBridgeSchedulerEC2Stopを指定する

AWSドキュメントに近い記載例

Mateoのポリシーを更新し、scheduler:GetWidgetアクションを使用してmy-example-widgetリソースへアクセスできるようにする

出典：EventBridge SchedulerのIAMトラブルシューティング

使用する表

入力値、比較、確認結果など、同じ項目を繰り返し説明する場合は表を使用する。文章だけで説明できる内容を無理に表へ変換しない

<PROFILE_NAME>既定以外の認証情報を利用する場合のプロファイル名任意

コールアウト

本文から分離して認識させる必要がある情報だけをコールアウトで表示する。通常の説明をすべてコールアウトにしない

ℹ️ 情報 仕様、前提条件、補足、利用できる代替手段を記載する
⚠️ 注意 データ削除、停止、再起動、権限変更など、実行前に判断が必要な影響を記載する
✅ 成功 コマンドの実行結果や設定値が期待する状態になったことを示す
❌ エラー 想定されるエラー、原因、作業を中止する条件、切り戻し判断を記載する

そのほかの構成要素

OSや方式ごとにコマンドが異なる場合はタブを使用し、長い実行例や補足は折りたたみ表示を使用する

タブ

PowerShell
Get-Service -Name AmazonCloudWatchAgent
bash
systemctl status amazon-cloudwatch-agent.service

折りたたみ

実行例を展開する

初期表示では必須ではない長い実行例、出力例、補足画像を格納する

CloudShell
aws ec2 describe-instances --query "Reservations[].Instances[].InstanceId" --output table
