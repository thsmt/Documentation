Amazon SES

Amazon SESによるメール送信と配信運用の手順を整理する

Amazon SES作成

送信経路は、アプリケーション → Postfix → SES SMTPエンドポイント（TCP 587）→ 宛先メールサーバーとなる。SES IDが未作成または削除済みの場合は、ドメインIDの作成から開始する

1. ドメインIDとEasy DKIMを作成

  1. Amazon SESコンソールで利用リージョンを選択
  2. 「設定」→「ID」→「IDの作成」を選択
  3. IDタイプで「ドメイン」を選択し、送信ドメインを入力
  4. Easy DKIMを選択し、DNSレコードの発行方法を指定
  5. SESが提示するDKIM用CNAMEレコードをDNSへ登録
  6. IDのステータスが「検証済み」、DKIMが「成功」になることを確認
ℹ️ SESサンドボックス

サンドボックスでは、検証済みIDから検証済み宛先へだけ送信できる。外部の任意アドレスへ送信する本番用途では、SESコンソールから本稼働アクセスを申請する

SMTP認証情報

2. Postfix専用のSMTP認証情報を作成

  1. Amazon SESコンソールの「SMTP設定」を選択
  2. 「SMTP認証情報の作成」を選択
  3. 用途を識別できるSMTP用IAMユーザー名を入力
  4. ユーザーを作成し、SMTPユーザー名とSMTPパスワードを安全な保管先へ保存
⚠️ リージョンとパスワード

SMTP認証情報はリージョンごとに異なる。SMTPパスワードはAWSシークレットアクセスキーとは別の値であり、画面を閉じた後は再表示できない

PostfixからSES SMTPへリレー

AWS公式のIntegrating Amazon SES with Postfixを基に、SASL認証とSTARTTLSを設定する

3. Postfix、SASL認証、メール送信テスト用パッケージを導入

LinuxサーバーからSES経由でメール送信するため、Postfix、SASL認証パッケージ、メール送信テスト用コマンドを導入する

root shell
dnf install -y postfix cyrus-sasl-plain mailx ca-certificates
root shell
apt-get update
DEBIAN_FRONTEND=noninteractive apt-get install -y postfix libsasl2-modules mailutils ca-certificates

4. 変更前の稼働状態と設定を記録

systemctl statusで、Postfixサービスが稼働中か、停止・失敗していないかを確認する

root shell
systemctl status postfix --no-pager

postconf -nで、初期値から変更されているPostfixの有効な設定を記録する

root shell
postconf -n

postqueue -pで、作業前から送信待ちまたは配送できていないメールがないかを確認する

root shell
postqueue -p

5. Postfix設定ファイルのバックアップ取得

バックアップ取得前に既存ファイルを確認し、コピー後に日付付きファイルが作成されたことを確認する

root shell
ls -la /etc/postfix/main.cf*
ls -la /etc/postfix/master.cf*
cp -pi /etc/postfix/main.cf /etc/postfix/main.cf.`date +%Y%m%d`
cp -pi /etc/postfix/master.cf /etc/postfix/master.cf.`date +%Y%m%d`
ls -la /etc/postfix/main.cf*
ls -la /etc/postfix/master.cf*

6. main.cfを編集

hostname -fでOSが認識するFQDN、postconf myhostnameでPostfixが使用するホスト名を確認する。値が実際のサーバーFQDNと異なる場合は、myhostnameを設定する

root shell
hostname -f
postconf myhostname
vi /etc/postfix/main.cf

次の例は東京リージョンを使用する。mail.example.comは実際のサーバーFQDNへ変更し、別リージョンではSMTPエンドポイントを変更する

/etc/postfix/main.cf
myhostname = mail.example.com

relayhost = [email-smtp.ap-northeast-1.amazonaws.com]:587
smtp_sasl_auth_enable = yes
smtp_sasl_security_options = noanonymous
smtp_sasl_password_maps = hash:/etc/postfix/sasl_passwd
smtp_use_tls = yes
smtp_tls_security_level = secure
smtp_tls_note_starttls_offer = yes

7. フォールバックリレー設定を確認

/etc/postfix/master.cfに-o smtp_fallback_relay=がある場合は、その行をコメントアウトする

root shell
grep -n 'smtp_fallback_relay' /etc/postfix/master.cf
vi /etc/postfix/master.cf

8. SMTP認証情報を登録してハッシュDBを作成

root shell
vi /etc/postfix/sasl_passwd
/etc/postfix/sasl_passwd
[email-smtp.ap-northeast-1.amazonaws.com]:587 SES_SMTP_USERNAME:SES_SMTP_PASSWORD
root shell
postmap hash:/etc/postfix/sasl_passwd
chown root:root /etc/postfix/sasl_passwd /etc/postfix/sasl_passwd.db
chmod 0600 /etc/postfix/sasl_passwd /etc/postfix/sasl_passwd.db
ls -la /etc/postfix/sasl_passwd /etc/postfix/sasl_passwd.db

9. CA証明書ファイルを設定

/etc/postfix/main.cf
smtp_tls_CAfile = /etc/pki/tls/certs/ca-bundle.crt
/etc/postfix/main.cf
smtp_tls_CAfile = /etc/ssl/certs/ca-certificates.crt

10. 設定差分と構文を確認してPostfixへ反映

root shell
diff -u /etc/postfix/main.cf.`date +%Y%m%d` /etc/postfix/main.cf
diff -u /etc/postfix/master.cf.`date +%Y%m%d` /etc/postfix/master.cf

postfix check
postconf -n | grep -E '^(myhostname|relayhost|smtp_sasl|smtp_use_tls|smtp_tls)'
systemctl enable postfix
systemctl restart postfix
systemctl status postfix --no-pager

11. 検証済みの送信元からテストメールを送信

SESサンドボックスでは、検証済みの宛先を指定する

カスタムMAIL FROM設定

SESの既定MAIL FROMを、自社が管理する専用サブドメインへ変更する。表示用のFromアドレスではなく、バウンス処理とSPF認証に使うエンベロープFromを変更する設定となる

設定すると何が変わるか

観点設定前設定後
受信者に表示されるFromno-reply@example.com通常は変わらない
Return-PathSESが用意するamazonses.com配下bounce.example.comなど自社管理のサブドメイン
SPFSES既定MAIL FROMに対して検証自社のMAIL FROMサブドメインに公開したSPFで検証
DMARC主にDKIM整合で成立Header Fromと親ドメインをそろえることで、SPF整合も利用可能
受信者からの見え方通常のメール画面に大きな差はなく、詳細ヘッダーを開くとReturn-PathとSPF認証ドメインの違いを確認できる
ℹ️ 到達率への影響

カスタムMAIL FROMを設定しただけで到達率が上がるわけではない。SPF、DKIM、DMARCの整合性を高め、受信側が送信元を検証しやすくするため、到達性の基盤を整える設定となる。DNSレコードが誤っている場合は、選択したMX障害時動作によりSES既定MAIL FROMへ戻るか、送信自体が拒否される

1. 検証済みドメインIDでカスタムMAIL FROMを有効化

  1. SESコンソールの「ID」から検証済みドメインIDを選択
  2. 「カスタムMAIL FROMドメイン」の「編集」を選択
  3. 「カスタムMAIL FROMドメインを使用」を有効化
  4. 専用サブドメインを入力
  5. MX障害時の動作として、SES既定MAIL FROMの使用またはメッセージ拒否を選択
  6. 変更を保存
⚠️ 専用サブドメイン

カスタムMAIL FROMは検証済み親ドメインのサブドメインとし、通常の送信元や受信先には使用しない。MAIL FROMサブドメインに登録するMXレコードはSES用の1件だけとする

DNSレコード登録

2. SESが提示するMXレコードとSPF用TXTレコードを登録

種類名前の例値
MXbounce.example.com10 feedback-smtp.ap-northeast-1.amazonses.com
TXTbounce.example.com"v=spf1 include:amazonses.com ~all"

Route 53を同じAWSアカウントで管理している場合は、SESの「Route 53を使用してレコードを発行」から登録できる。別のDNS事業者を利用する場合は、表示された値をDNS管理画面へ登録する

DNS反映確認

3. MXとTXTの応答を確認

shell
dig MX bounce.example.com
dig TXT bounce.example.com
powershell
Resolve-DnsName bounce.example.com -Type MX
Resolve-DnsName bounce.example.com -Type TXT

4. SESの状態と受信メールのReturn-Pathを確認

  1. SESのカスタムMAIL FROM状態が「成功」になることを確認
  2. テストメールを再送
  3. 受信メールの詳細ヘッダーを開き、Return-Pathが設定したサブドメインであることを確認
  4. SPF、DKIM、DMARCの結果を確認

DNS事業者によっては、SESがMXレコードを検出するまで最大72時間かかる。手順の根拠: Using a custom MAIL FROM domain、Complying with DMARC authentication protocol in Amazon SES

Virtual Deliverability Manager（VDM）

VDMは、SESの配信状況と送信者評価を分析し、到達性の改善に使う。アカウント単位で有効化した後、構成セット単位でエンゲージメント追跡と最適化された共有配信を上書きできる

1. アカウントでVDMを有効化

  1. SESコンソールから「Virtual Deliverability Manager」を選択
  2. 「Virtual Deliverability Managerの使用を開始する」を選択
  3. エンゲージメント追跡の有効または無効を選択
  4. 最適化された共有配信の有効または無効を選択
  5. 設定内容を確認してVDMを有効化
機能効果設計上の注意
エンゲージメント追跡開封とクリックのイベントを収集トラッキングピクセルとラップURLにより、本文内のURLが変化
最適化された共有配信送信先に応じて共有IPの選択を最適化送信者評価を保護するため、送信が事前に遅延する場合あり
構成セットメール種別ごとにVDM設定を上書きマーケティングメールと即時性が必要な通知を分離

2. 用途別の構成セットを作成

  1. SESコンソールの「構成セット」から用途別の構成セットを作成
  2. 構成セットのVirtual Deliverability Managerオプションを開く
  3. エンゲージメント追跡と最適化された共有配信について、アカウント設定の継承または個別設定を選択
  4. 遅延を許容できない通知では最適化された共有配信を無効化し、マーケティングメールと分離

3. SMTP送信時に構成セットを指定

mail header
X-SES-CONFIGURATION-SET: transactional-mail

4. VDMダッシュボードで送信結果を確認

  1. 構成セットを指定したテストメールを送信
  2. VDMダッシュボードで配信、バウンス、苦情の指標を確認
  3. エンゲージメント追跡を有効化した場合は、開封とクリックの記録を確認
⚠️ 即時性と料金

遅延を許容できない通知では、最適化された共有配信を一律に有効化せず、構成セットで対象を分離する。VDMを含むSESの料金体系は変更されるため、有効化前にAmazon SES料金を確認する

手順の根拠: Getting started with Virtual Deliverability Manager、Virtual Deliverability Manager settings、Specifying a configuration set when you send email
