ストレージ管理

⚡ このページの要約

RHEL 9におけるブロックデバイス、GPT、XFS、LVMの構築と保守手順を整理する
iSCSIとDevice Mapper Multipathを含め、変更前確認から障害切り分けまでをまとめる

1. デバイスと利用状況の確認

デバイス名は再起動や接続順で変わる場合があるため、作業対象を容量、モデル、シリアル、WWN、マウント先で特定する

1.1 ブロックデバイスの確認

user shell
lsblk -e 7 -o NAME,PATH,SIZE,TYPE,FSTYPE,FSVER,LABEL,UUID,MOUNTPOINTS,MODEL,SERIAL,WWN

1.2 ファイルシステムとLVMの確認

root shell
findmnt --real
df -hT
blkid
pvs -o+devices
vgs
lvs -a -o+devices,segtype
⚠️ 作業対象の特定

<DEVICE>と<PARTITION>は実機の確認結果へ置き換える。OSディスクや使用中デバイスへパーティション作成、フォーマット、PV作成を実行しない

2. GPTパーティションとXFSの作成

新規データディスクへGPTパーティションとXFSを作成し、UUIDで永続マウントする

2.1 使用中でないことの確認

root shell
lsblk -f <DEVICE>
findmnt --source <DEVICE>

2.2 GPTとパーティションの作成

root shell
parted <DEVICE> --script mklabel gpt
parted <DEVICE> --script mkpart primary xfs 1MiB 100%
partprobe <DEVICE>

2.3 XFSの作成と一時マウント

root shell
mkfs.xfs -L <FILESYSTEM_LABEL> <PARTITION>
install -d -m 0755 <MOUNT_POINT>
mount <PARTITION> <MOUNT_POINT>
blkid <PARTITION>

2.4 /etc/fstabのバックアップと編集

root shell
cp -pi /etc/fstab /etc/fstab.$(date +%Y%m%d)
vi /etc/fstab
fstab
UUID=<FILESYSTEM_UUID>  <MOUNT_POINT>  xfs  defaults,nofail  0  0

2.5 永続マウント設定の確認

root shell
umount <MOUNT_POINT>
systemctl daemon-reload
mount -a
findmnt <MOUNT_POINT>
findmnt --verify --verbose

3. XFSの拡張・バックアップ・修復

XFSはオンライン拡張に対応するが縮小には対応しない。縮小が必要な場合は新しい小容量ファイルシステムを作成してデータを移行する

3.1 デバイス拡張後のXFS拡張

root shell
xfs_growfs <MOUNT_POINT>
df -hT <MOUNT_POINT>

3.2 バックアップツールのインストール

root shell
dnf install xfsdump

3.3 バックアップの取得と復元

root shell
xfsdump -l 0 -L <DUMP_LABEL> -M <MEDIA_LABEL> -f <BACKUP_FILE> <MOUNT_POINT>
xfsrestore -f <BACKUP_FILE> <RESTORE_DIRECTORY>

3.4 ログ再生後のアンマウントと検査

root shell
umount <MOUNT_POINT>
mount <PARTITION> <MOUNT_POINT>
umount <MOUNT_POINT>
xfs_repair -n <PARTITION>

3.5 バックアップ取得後の修復

root shell
xfs_metadump <PARTITION> <METADUMP_FILE>
xfs_repair <PARTITION>
⚠️ 修復前の保全

xfs_repairはファイルシステムを変更する。可能な限りスナップショットまたはブロックレベルバックアップを取得し、最初に-nで検査する

4. LVMの作成と拡張

PV、VG、LVを分離して管理し、ファイルシステムの停止時間を抑えて容量を拡張する

4.1 PVとVGの作成

root shell
pvcreate <LVM_DEVICE>
vgcreate <VG_NAME> <LVM_DEVICE>

4.2 LVとXFSの作成

root shell
lvcreate -L <LV_SIZE> -n <LV_NAME> <VG_NAME>
mkfs.xfs /dev/<VG_NAME>/<LV_NAME>

4.3 LVとXFSの同時拡張

root shell
lvextend --resizefs -L +<ADDITIONAL_SIZE> /dev/<VG_NAME>/<LV_NAME>

4.4 LVMメタデータバックアップの確認

root shell
vgcfgbackup <VG_NAME>
ls -l /etc/lvm/backup/<VG_NAME>

5. スナップショット・シンプロビジョニング・RAID

スナップショットは短期的な整合点であり、別媒体へ退避するバックアップの代替にはしない

5.1 COWスナップショットの作成

root shell
lvcreate --snapshot -L <SNAPSHOT_SIZE> -n <SNAPSHOT_NAME> /dev/<VG_NAME>/<LV_NAME>

5.2 シンプールとシンLVの作成

root shell
lvcreate --type thin-pool -L <POOL_SIZE> -n <THIN_POOL> <VG_NAME>
lvcreate --type thin -V <VIRTUAL_SIZE> -T <VG_NAME>/<THIN_POOL> -n <THIN_LV>

5.3 LVM RAID1の作成

root shell
lvcreate --type raid1 -m 1 -L <LV_SIZE> -n <LV_NAME> <VG_NAME>

5.4 使用率と同期状態の確認

root shell
lvs -a -o lv_name,origin,segtype,data_percent,metadata_percent,copy_percent
ℹ️ 容量監視

シンプールとスナップショットは領域枯渇でI/O障害を起こす可能性がある。data_percentとmetadata_percentを監視し、閾値到達前に拡張する

6. LVM-VDOによる重複排除と圧縮

VDOは物理容量より大きい仮想容量を提示するため、実データ使用量を継続監視し、物理領域の枯渇を防止する

6.1 VDOパッケージのインストール

root shell
dnf install lvm2 kmod-kvdo vdo

6.2 LVM-VDOの作成

root shell
lvcreate --type vdo --name <VDO_LV_NAME> --vdopool <VDO_POOL_NAME> --size <PHYSICAL_POOL_SIZE> --virtualsize <VIRTUAL_SIZE> <VG_NAME>

6.3 XFSの作成

root shell
mkfs.xfs -K /dev/<VG_NAME>/<VDO_LV_NAME>

6.4 VDO使用率の確認

root shell
lvs -o lv_name,vg_name,segtype,lv_size,data_percent
vdostats --human-readable
⚠️ オーバープロビジョニング

仮想容量ではなくVDOプールの物理使用率を監視する。重複排除率や圧縮率を前提に容量設計せず、低減効果がない状態でも枯渇しない運用閾値を定義する

7. iSCSIの構成

ターゲット側でLUNと接続元ACLを設定し、イニシエーター側で検出・ログインする

7.1 ターゲットのインストールと起動

target root
dnf install targetcli
systemctl enable --now target

7.2 バックストア・IQN・LUN・ACLの設定

targetcli
targetcli
/backstores/block create <BACKSTORE_NAME> <BLOCK_DEVICE>
/iscsi create <TARGET_IQN>
/iscsi/<TARGET_IQN>/tpg1/luns create /backstores/block/<BACKSTORE_NAME>
/iscsi/<TARGET_IQN>/tpg1/acls create <INITIATOR_IQN>
saveconfig
exit

7.3 iSCSIポートの許可

target root
firewall-cmd --permanent --add-service=iscsi-target
firewall-cmd --reload

7.4 イニシエーターのインストールと接続

initiator root
dnf install iscsi-initiator-utils
cat /etc/iscsi/initiatorname.iscsi
iscsiadm -m discovery -t sendtargets -p <TARGET_ADDRESS>
iscsiadm -m node -T <TARGET_IQN> -p <TARGET_ADDRESS> --login
iscsiadm -m session

8. Device Mapper Multipathの構成

同じLUNへの複数経路を単一デバイスへ統合し、経路障害時の継続性を確保する

8.1 パッケージのインストールと有効化

root shell
dnf install device-mapper-multipath
mpathconf --enable
systemctl enable --now multipathd

8.2 経路とマルチパスデバイスの確認

root shell
multipath -ll
multipathd show paths
multipathd show maps
⚠️ 単一経路での書き込み禁止

マルチパス化したLUNは/dev/mapper/<MULTIPATH_NAME>を使用する。配下の個別/dev/sdXへファイルシステムを作成しない

9. 運用確認

確認対象確認方法
容量df -hT、lvs、シンプール使用率を監視
マウントfindmnt --verifyとmount -aで永続設定を確認
I/Oエラーjournalctl -kとストレージ装置側イベントを確認
iSCSIiscsiadm -m sessionでセッションを確認
Multipathmultipath -llで全経路の状態を確認
復元性バックアップから別領域への復元を定期確認

9.1 カーネルログにおけるI/Oエラーの確認

root shell
journalctl -k -p warning..alert --since today
