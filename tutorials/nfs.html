NFS

⚡ このページの要約

RHEL 9でNFSv4共有を構築し、接続元を限定したエクスポートと永続マウントを設定する
ACL、autofs、NFSv3互換、Kerberos保護を含む運用ポイントを整理する

1. 構成パラメータの確認

NFSv4.2を優先し、サーバーとクライアントでUID・GIDを一致させる。Kerberosを使用しない構成では、ホスト名解決と接続元制限を必須とする

項目パラメータ
NFSサーバー<NFS_SERVER_FQDN>
エクスポート先/srv/nfs/<SHARE_NAME>
許可する接続元<NFS_CLIENT_CIDR>
クライアント側マウント先<MOUNT_POINT>
推奨プロトコルNFSv4.2
⚠️ IDマッピング

NFSのアクセス権は数値UID・GIDの一致に依存する。ローカルアカウントを個別作成する場合も、サーバーと全クライアントで同じUID・GIDを割り当てる

2. NFSサーバーのインストール

2.1 パッケージのインストール

server root
dnf install nfs-utils

2.2 NFSv4優先設定の確認

server shell
nfsconf --get nfsd vers4
nfsconf --get nfsd vers3

2.3 サービスの有効化

server root
systemctl enable --now nfs-server

3. NFS共有の作成

root_squashを維持し、クライアントのrootをサーバー側rootとして扱わない

3.1 共有ディレクトリの作成

server root
install -d -o <OWNER_USER> -g <OWNER_GROUP> -m 2770 /srv/nfs/<SHARE_NAME>

3.2 エクスポート設定のバックアップ

server root
cp -pi /etc/exports /etc/exports.$(date +%Y%m%d)

3.3 エクスポート設定の編集

server root
vi /etc/exports
exports
/srv/nfs/<SHARE_NAME>  <NFS_CLIENT_CIDR>(rw,sync,root_squash,no_subtree_check)

3.4 エクスポート設定の反映と確認

server root
exportfs -rav
exportfs -v

4. NFSv4の通信許可

NFSv4のみを使用する構成では主に2049/TCPを使用する。クラウド側ファイアウォールでも同じ接続元へ限定する

4.1 firewalldの有効ゾーン確認

server root
firewall-cmd --get-active-zones

4.2 NFSサービスの許可

server root
firewall-cmd --permanent --zone=<ACTIVE_ZONE> --add-rich-rule='rule family="ipv4" source address="<NFS_CLIENT_CIDR>" service name="nfs" accept'
firewall-cmd --reload
firewall-cmd --zone=<ACTIVE_ZONE> --list-rich-rules

4.3 待受ポートの確認

server shell
ss -lnt | grep ':2049'

5. NFSクライアントの設定

5.1 クライアントパッケージのインストール

client root
dnf install nfs-utils

5.2 名前解決とポート疎通の確認

client shell
getent ahosts <NFS_SERVER_FQDN>
nc -vz <NFS_SERVER_FQDN> 2049

5.3 NFSv4.2による一時マウント

client root
install -d -m 0755 <MOUNT_POINT>
mount -t nfs -o nfsvers=4.2 <NFS_SERVER_FQDN>:/srv/nfs/<SHARE_NAME> <MOUNT_POINT>
findmnt <MOUNT_POINT>

5.4 永続マウント設定の追加

client root
cp -pi /etc/fstab /etc/fstab.$(date +%Y%m%d)
vi /etc/fstab
fstab
<NFS_SERVER_FQDN>:/srv/nfs/<SHARE_NAME>  <MOUNT_POINT>  nfs  nfsvers=4.2,_netdev,nofail,x-systemd.automount  0  0

5.5 永続マウント設定の確認

client root
umount <MOUNT_POINT>
systemctl daemon-reload
mount -a
findmnt --verify --verbose
ls <MOUNT_POINT>

6. autofsによるオンデマンドマウント

アクセス時だけマウントし、長時間未使用のNFS接続を自動解除する

6.1 autofsのインストール

client root
dnf install autofs

6.2 マスターマップの作成

client root
vi /etc/auto.master.d/nfs.autofs
auto.master
/mnt/nfs  /etc/auto.nfs  --timeout=300

6.3 間接マップの作成

client root
vi /etc/auto.nfs
auto.nfs
<SHARE_NAME>  -fstype=nfs4,nfsvers=4.2  <NFS_SERVER_FQDN>:/srv/nfs/<SHARE_NAME>

6.4 autofsの有効化と確認

client root
automount -m
systemctl enable --now autofs
ls /mnt/nfs/<SHARE_NAME>

7. ACLの設定

NFSv4 ACLを使用する場合は、サーバーとクライアントへ操作ツールを導入する

7.1 NFSv4 ACLツールのインストール

root shell
dnf install nfs4-acl-tools

7.2 ACLの確認

user shell
nfs4_getfacl <MOUNT_POINT>/<FILE_NAME>

7.3 ユーザーACLの追加

root shell
nfs4_setfacl -a 'A::<USER_NAME>:rwaDxtTnNcCy' <MOUNT_POINT>/<FILE_NAME>

8. Kerberosで保護するNFSv4

IdMまたはKerberos環境でNFSサービスプリンシパルとkeytabを配布し、完全修飾ドメイン名と時刻同期を使用する

セキュリティ方式保護内容
krb5認証
krb5i認証と完全性
krb5p認証、完全性、通信内容の暗号化

8.1 サービスプリンシパルとkeytabの確認

server root
klist -k /etc/krb5.keytab | grep 'nfs/<NFS_SERVER_FQDN>'

8.2 Kerberos保護エクスポートの設定

exports
/srv/nfs/<SHARE_NAME>  <NFS_CLIENT_CIDR>(rw,sync,root_squash,no_subtree_check,sec=krb5p)

8.3 Kerberos保護マウントの確認

client root
mount -t nfs4 -o sec=krb5p <NFS_SERVER_FQDN>:/srv/nfs/<SHARE_NAME> <MOUNT_POINT>
nfsstat -m

9. NFSv3互換を有効にする場合

NFSv3クライアントが存在する場合だけrpcbindとmountdを許可し、使用ポートを固定してファイアウォール管理する

9.1 NFSv3関連サービスの許可

server root
firewall-cmd --permanent --zone=<ACTIVE_ZONE> --add-service=rpc-bind
firewall-cmd --permanent --zone=<ACTIVE_ZONE> --add-service=mountd
firewall-cmd --reload

9.2 エクスポート一覧の確認

client shell
showmount -e <NFS_SERVER_FQDN>

10. 運用確認

確認対象確認方法
サービスsystemctl status nfs-server
エクスポートexportfs -v
マウント方式nfsstat -m
クライアント接続ss -tn sport = :2049
権限所有者、数値UID・GID、ACLを確認
ログjournalctl -u nfs-serverとカーネルログを確認

10.1 サーバー状態とログの確認

server root
systemctl status nfs-server --no-pager
journalctl -u nfs-server -p warning..alert --since today
