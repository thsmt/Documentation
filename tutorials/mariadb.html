MariaDB

RHEL 8 / 9でMariaDBのバージョン選択、インストール、サーバー設定、クライアント更新、バックアップを行う手順

⚠️ MariaDBとMySQLの同居不可

RHELのMariaDBとMySQLは競合するRPMパッケージが同じ実行ファイル、ライブラリ、設定領域を提供するため、同一システムへ同時にインストールできない

複数バージョンやMariaDBとMySQLを同一ホストで使用する場合は、ポートとコンテナ名を分けたコンテナ構成を選択

1. RHEL別の提供バージョン確認

OSバージョン無指定時AppStreamで提供されるバージョン提供形態
RHEL 8 MariaDB 10.3の既定ストリーム 10.3、10.5（RHEL 8.4以降）、10.11（RHEL 8.10以降） すべてモジュールストリーム
RHEL 9 MariaDB 10.5の非モジュールRPM 10.11（RHEL 9.4以降）、11.8（RHEL 9.8以降） 10.5はRPM、10.11と11.8はモジュールストリーム

バージョン無指定時の版は推奨版を意味しないため、導入前に対象RHELのマイナーバージョン、利用可能なストリーム、Application Streamsのライフサイクルを確認

2026年8月時点でRHEL 8のMariaDB 10.5はサポート終了。提供済みストリームがサポート中とは限らないため、新規構築ではライフサイクルを確認して版を選択

RHEL 9.8で追加されたMariaDB 11.8は、既定の文字セットがutf8mb4へ変更され、mysqlなどの旧コマンド名は互換シンボリックリンクとして扱われるため、新規手順ではmariadb系コマンドを使用

出典：Red Hat Enterprise Linux 8 - Database servers

出典：Red Hat Enterprise Linux 9 - Using MariaDB

出典：Red Hat Enterprise Linux Application Streams Life Cycle

2. インストールと起動

2.1 OSと既存パッケージの確認

RHELリリースの確認

shell
cat /etc/redhat-release

MariaDBモジュールストリームの確認

shell
dnf module list mariadb

MariaDBまたはMySQLの既存パッケージ確認

shell
rpm -qa | grep -Ei '^(mariadb|mysql)'

2.2 バージョン無指定でのサーバーインストール

RHEL 8の既定ストリームとserverプロファイルのインストール

RHEL 8
dnf module install mariadb/server

RHEL 9の非モジュールRPM版のインストール

RHEL 9
dnf install mariadb-server

2.3 バージョン指定でのサーバーインストール

RHEL 8またはRHEL 9で利用可能なストリームとserverプロファイルの指定

shell
dnf module install mariadb:<STREAM>/server

2.4 サービスの有効化と起動

MariaDBサービスの有効化と起動

shell
systemctl enable --now mariadb.service

MariaDBサービス状態の確認

shell
systemctl status mariadb.service --no-pager

MariaDBバージョンの確認

MariaDB 10.3
mysql --version
MariaDB 10.5+
mariadb --version

管理者としてのローカル接続確認

MariaDB 10.3
mysql
MariaDB 10.5+
mariadb
ℹ️ 初期セキュリティ確認

RHEL 8のMariaDB 10.3ではmysql_secure_installationを実行。MariaDB 10.5以降はrootのUNIXソケット認証などが既定で設定されるため、このスクリプトを前提にせず各項目を個別に確認

MariaDB 10.3における対話式の初期セキュリティ設定

MariaDB 10.3
mysql_secure_installation

ユーザー、接続元、認証プラグインの確認

MariaDB 10.3
mysql -e "SELECT User,Host,plugin FROM mysql.user ORDER BY User,Host;"
MariaDB 10.5+
mariadb -e "SELECT User,Host,plugin FROM mysql.user ORDER BY User,Host;"

3. 設定ファイルと基本設定

パス用途
/etc/my.cnfMariaDBとMySQL互換クライアントが読み込む主設定ファイル
/etc/my.cnf.d/mariadb-server.cnfRHELが提供するMariaDBサーバー設定
/etc/my.cnf.d/99-local.cnfサイト固有設定を分離する追加ファイル
/etc/my.cnf.d/client.cnfクライアントの共通設定
/var/lib/mysql標準データディレクトリ

3.1 配布設定ファイルのバックアップ

MariaDBサーバー設定のバックアップ

shell
cp -p /etc/my.cnf.d/mariadb-server.cnf /etc/my.cnf.d/mariadb-server.cnf.bak

3.2 サイト固有設定の作成

サイト固有設定ファイルの編集

shell
vi /etc/my.cnf.d/99-local.cnf
/etc/my.cnf.d/99-local.cnf
[mysqld]
bind-address = <DB_SERVER_PRIVATE_IP>
port = 3306
character-set-server = utf8mb4
collation-server = utf8mb4_unicode_ci

カスタムポートを使用する場合は、このportと後述するSELinux、firewalld、接続コマンドのポート番号を同じ値へ変更

3.3 クライアント文字セット設定の作成

クライアント設定ファイルの編集

shell
vi /etc/my.cnf.d/99-client-local.cnf
/etc/my.cnf.d/99-client-local.cnf
[client]
default-character-set = utf8mb4

3.4 TLS証明書と秘密鍵の権限設定

PEM形式のサーバー証明書、CA証明書、秘密鍵を配置した後の公開証明書権限設定

shell
chmod 0644 /etc/pki/tls/certs/<DB_FQDN>.crt.pem /etc/pki/tls/certs/ca.crt.pem

秘密鍵をMariaDBだけが読み取れる権限とグループへ変更

shell
chmod 0640 /etc/pki/tls/private/<DB_FQDN>.key.pem
shell
chgrp mysql /etc/pki/tls/private/<DB_FQDN>.key.pem

証明書ディレクトリのSELinuxコンテキスト復元

shell
restorecon -Rv /etc/pki/tls

3.5 TLSサーバー設定とクライアント設定の作成

MariaDBサーバーのTLS設定ファイル編集

shell
vi /etc/my.cnf.d/mariadb-server-tls.cnf
MariaDB 10.3
[mariadb]
ssl_key = /etc/pki/tls/private/<DB_FQDN>.key.pem
ssl_cert = /etc/pki/tls/certs/<DB_FQDN>.crt.pem
ssl_ca = /etc/pki/tls/certs/ca.crt.pem
MariaDB 10.5+
[mariadb]
ssl_key = /etc/pki/tls/private/<DB_FQDN>.key.pem
ssl_cert = /etc/pki/tls/certs/<DB_FQDN>.crt.pem
ssl_ca = /etc/pki/tls/certs/ca.crt.pem
require_secure_transport = on
tls_version = TLSv1.2,TLSv1.3

MariaDBクライアントのTLS検証設定ファイル編集

shell
vi /etc/my.cnf.d/mariadb-client-tls.cnf
/etc/my.cnf.d/mariadb-client-tls.cnf
[client]
ssl
ssl-ca = /etc/pki/tls/certs/ca.crt.pem
ssl-verify-server-cert
⚠️ TLS証明書のホスト名

サーバー証明書のSANと接続時の<DB_FQDN>を一致させ、クライアント側にも検証に使用するCA証明書を安全に配置

3.6 設定反映と確認

⚠️ MariaDB 10.3のTLS制約

require_secure_transportとtls_versionはMariaDB 10.3で使用できないため、10.3ではリモートユーザーへREQUIRE SSLを指定して暗号化接続を必須化

MariaDBサービスの再起動

shell
systemctl restart mariadb.service

設定値の確認

MariaDB 10.3
mysql -e "SHOW VARIABLES WHERE Variable_name IN ('bind_address','port','character_set_server','collation_server','have_ssl');"
MariaDB 10.5+
mariadb -e "SHOW VARIABLES WHERE Variable_name IN ('bind_address','port','character_set_server','collation_server','have_ssl','require_secure_transport','tls_version');"

4. ポートとリモート接続設定

既定ポート3306を使用する場合、SELinuxのポート登録変更は不要

4.1 カスタムポート使用時のSELinuxツール導入

shell
dnf install policycoreutils-python-utils

4.2 カスタムポートのSELinux登録

現在のMariaDB用ポート登録の確認

shell
semanage port -l | grep mysqld_port_t

未登録のカスタムポート追加

shell
semanage port -a -t mysqld_port_t -p tcp <DB_PORT>

同じポートに別のSELinuxタイプが登録済みの場合は、追加ではなく-mによる変更可否を確認

4.3 接続元を限定したfirewalld設定

NICが属するアクティブゾーンの確認

shell
firewall-cmd --get-active-zones

確認したゾーンへ接続元を限定した許可を追加

shell
firewall-cmd --permanent --zone=<ACTIVE_ZONE> --add-rich-rule='rule family="ipv4" source address="<APP_SERVER_CIDR>" port protocol="tcp" port="<DB_PORT>" accept'

firewalld設定の再読み込み

shell
firewall-cmd --reload

MariaDBの待受確認

shell
ss -lntp | grep ':<DB_PORT>'
⚠️ 公開範囲の制限

bind-address = 0.0.0.0や全インターネット向けの3306番公開を避け、DBサーバーのプライベートIP、アプリケーションサーバーのCIDR、Security Group、firewalldを一致

5. データベースとユーザーの作成

アプリケーション用データベースの作成

SQL
CREATE DATABASE <APP_DATABASE> CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

接続元を限定したアプリケーション用ユーザーの作成

SQL
CREATE USER '<APP_USER>'@'<APP_SERVER_HOST>' IDENTIFIED BY '<STRONG_PASSWORD>' REQUIRE SSL;

必要なデータ操作権限の付与

SQL
GRANT SELECT, INSERT, UPDATE, DELETE ON <APP_DATABASE>.* TO '<APP_USER>'@'<APP_SERVER_HOST>';

付与済み権限の確認

SQL
SHOW GRANTS FOR '<APP_USER>'@'<APP_SERVER_HOST>';

アプリケーション用ユーザーによる接続確認

MariaDB 10.3
mysql --host=<DB_FQDN> --port=<DB_PORT> --user=<APP_USER> --password <APP_DATABASE>
MariaDB 10.5+
mariadb --host=<DB_FQDN> --port=<DB_PORT> --user=<APP_USER> --password <APP_DATABASE>

TLSで使用中の暗号スイート確認

SQL
SHOW SESSION STATUS LIKE 'Ssl_cipher';

6. クライアントのインストールと更新

6.1 バージョン無指定でのクライアントインストール

RHEL 8の既定ストリームからclientプロファイルをインストール

RHEL 8
dnf module install mariadb/client

RHEL 9の非モジュールRPM版クライアントをインストール

RHEL 9
dnf install mariadb

6.2 バージョン指定でのクライアントインストール

shell
dnf module install mariadb:<STREAM>/client

6.3 現在のストリーム内でのクライアント更新

shell
dnf upgrade mariadb mariadb-connector-c

更新後のクライアントバージョン確認

MariaDB 10.3
mysql --version
MariaDB 10.5+
mariadb --version
⚠️ メジャーストリーム変更

通常のdnf upgradeは別のMariaDBストリームへ自動移行しない

サーバーパッケージが同居するホストでモジュールを切り替えるとDB本体も変更対象になるため、クライアント更新として実行せず、バックアップ、互換性確認、MariaDBの移行手順を適用

7. バックアップと復元

7.1 論理バックアップ用ディレクトリの作成

shell
install -d -m 0700 /var/backups/mariadb

7.2 データベースの論理バックアップ

RHEL 8のMariaDB 10.3でmysqldumpを使用したバックアップ

MariaDB 10.3
mysqldump --single-transaction --routines --events --triggers --databases <APP_DATABASE> --result-file=/var/backups/mariadb/<APP_DATABASE>.sql

MariaDB 10.5以降でmariadb-dumpを使用したバックアップ

MariaDB 10.5+
mariadb-dump --single-transaction --routines --events --triggers --databases <APP_DATABASE> --result-file=/var/backups/mariadb/<APP_DATABASE>.sql
ℹ️ 論理バックアップの範囲

アプリケーションDBだけのダンプにはMariaDBユーザーやサーバー設定を含まないため、必要な権限定義、/etc/my.cnf、/etc/my.cnf.d/も別途保全

7.3 SQLダンプからの復元

MariaDB 10.3
mysql --execute="source /var/backups/mariadb/<APP_DATABASE>.sql"
MariaDB 10.5+
mariadb --execute="source /var/backups/mariadb/<APP_DATABASE>.sql"

7.4 物理オンラインバックアップの作成

mariadb-backupパッケージのインストール

shell
dnf install mariadb-backup

バックアップ専用ユーザーの作成

SQL
CREATE USER '<BACKUP_USER>'@'localhost' IDENTIFIED BY '<STRONG_PASSWORD>';

物理バックアップに必要な権限の付与

SQL
GRANT RELOAD, LOCK TABLES, REPLICATION CLIENT ON *.* TO '<BACKUP_USER>'@'localhost';

空の物理バックアップ先ディレクトリ作成

shell
install -d -m 0700 /var/backups/mariadb/full

物理バックアップの取得

shell
mariabackup --backup --target-dir=/var/backups/mariadb/full --user=<BACKUP_USER> --password

物理バックアップのprepare処理

shell
mariabackup --prepare --target-dir=/var/backups/mariadb/full

7.5 物理バックアップからの復元

メンテナンス時間帯にMariaDBを停止

shell
systemctl stop mariadb.service

既存データディレクトリを退避

shell
mv /var/lib/mysql /var/lib/mysql.before-restore

空のデータディレクトリ作成

shell
install -d -o mysql -g mysql -m 0755 /var/lib/mysql

prepare済みバックアップのコピー

shell
mariabackup --copy-back --target-dir=/var/backups/mariadb/full

データディレクトリの所有者修正

shell
chown -R mysql:mysql /var/lib/mysql

SELinuxコンテキスト復元

shell
restorecon -RFv /var/lib/mysql

MariaDBサービスの起動

shell
systemctl start mariadb.service
⚠️ 復元テスト

物理バックアップ先は空または未作成であることを確認。復元先の/var/lib/mysql.before-restoreが既に存在する場合は上書きせず、別名へ退避

バックアップ成功だけで完了とせず、隔離環境で復元、テーブル件数、文字セット、アプリケーション接続を定期的に確認

8. Galera Clusterの構成

Galeraは複数ノードへ同期レプリケーションを行う構成であり、バックアップの代替ではない

8.1 Galeraパッケージのインストール

選択したMariaDBストリームのGaleraプロファイルをインストール

RHEL 8
dnf module install mariadb:<STREAM>/galera

Galera用パッケージをインストール

RHEL 9
dnf install mariadb-server-galera

8.2 Galera設定の編集

shell
vi /etc/my.cnf.d/galera.cnf
/etc/my.cnf.d/galera.cnf
[galera]
wsrep_on = 1
wsrep_cluster_name = "mariadb_cluster"
wsrep_cluster_address = "gcomm://<NODE1_PRIVATE_IP>,<NODE2_PRIVATE_IP>,<NODE3_PRIVATE_IP>"
wsrep_node_name = "<NODE_NAME>"
wsrep_node_address = "<NODE_PRIVATE_IP>"
wsrep_provider_options = "socket.ssl_key=/etc/pki/tls/private/<NODE_FQDN>.key.pem;socket.ssl_cert=/etc/pki/tls/certs/<NODE_FQDN>.crt.pem;socket.ssl_ca=/etc/pki/tls/certs/ca.crt.pem"
binlog_format = ROW
default_storage_engine = InnoDB
ℹ️ Galeraレプリケーション通信のTLS

wsrep_provider_optionsはGalera Providerによるレプリケーション通信を暗号化する。全ノードで共通のCA証明書を使用し、各ノード証明書のSANをノード名と一致させ、拡張キー用途にサーバー認証とクライアント認証を含める

既定のrsync方式によるSST通信はこの設定の対象外となるため、ノード間ネットワークを分離するか、採用するSST方式で別途暗号化を設定

出典：MariaDB - Securing Communications in Galera Cluster

8.3 Galeraノード間ポートの許可

firewalldの有効ゾーン確認

shell
firewall-cmd --get-active-zones

GaleraノードからのMariaDB接続許可

shell
firewall-cmd --permanent --zone=<ACTIVE_ZONE> --add-rich-rule='rule family="ipv4" source address="<GALERA_NODE_CIDR>" port protocol="tcp" port="<DB_PORT>" accept'

Galeraレプリケーション用TCPポートの許可

shell
firewall-cmd --permanent --zone=<ACTIVE_ZONE> --add-rich-rule='rule family="ipv4" source address="<GALERA_NODE_CIDR>" port protocol="tcp" port="4567" accept'

Galeraレプリケーション用UDPポートの許可

shell
firewall-cmd --permanent --zone=<ACTIVE_ZONE> --add-rich-rule='rule family="ipv4" source address="<GALERA_NODE_CIDR>" port protocol="udp" port="4567" accept'

IST用TCPポートの許可

shell
firewall-cmd --permanent --zone=<ACTIVE_ZONE> --add-rich-rule='rule family="ipv4" source address="<GALERA_NODE_CIDR>" port protocol="tcp" port="4568" accept'

SST用TCPポートの許可

shell
firewall-cmd --permanent --zone=<ACTIVE_ZONE> --add-rich-rule='rule family="ipv4" source address="<GALERA_NODE_CIDR>" port protocol="tcp" port="4444" accept'

firewalld設定の再読み込み

shell
firewall-cmd --reload
⚠️ Galeraのブートストラップ

全ノード間通信、TLS、設定したDBポート、4567/TCP・UDP、4568/TCP、4444/TCPを設計し、新規クラスタまたは全停止からの復旧時に選定した1ノードだけでブートストラップを実行

8.4 最初のノードのブートストラップ

first node only
galera_new_cluster

8.5 その他ノードの起動

other nodes
systemctl start mariadb.service

クラスタ状態の確認

MariaDB 10.3
mysql -e "SHOW STATUS WHERE Variable_name IN ('wsrep_cluster_size','wsrep_cluster_status','wsrep_ready','wsrep_local_state_comment');"
MariaDB 10.5+
mariadb -e "SHOW STATUS WHERE Variable_name IN ('wsrep_cluster_size','wsrep_cluster_status','wsrep_ready','wsrep_local_state_comment');"

9. 更新と日常確認

現在選択中のストリーム内におけるMariaDBパッケージ更新

shell
dnf upgrade 'mariadb*'
確認対象確認方法
サービスsystemctl status mariadb.service --no-pager
設定値SHOW VARIABLESで待受、ポート、文字セットを確認
接続アプリケーション用ユーザーと許可済み接続元から接続
ログjournalctl -u mariadb.service -bとMariaDBエラーログを確認
容量/var/lib/mysqlのファイルシステム容量とinodeを確認
復元性別環境への復元とアプリケーション疎通を確認

メジャーバージョン変更では設定互換性とデータ移行が必要になるため、通常のパッケージ更新と分離し、Red Hatが対象ストリームに示す移行手順を使用
