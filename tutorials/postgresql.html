PostgreSQL

RHEL 8 / 9でPostgreSQLのバージョン選択、インストール、認証設定、ロール管理、クライアント更新、バックアップを行う手順

⚠️ メジャーバージョンの選択

PostgreSQLモジュールは同一システムで同時に1ストリームだけを選択できる

バージョン無指定で導入される版がサポート中の推奨版とは限らないため、導入前に利用可能なストリームとApplication Streamsのライフサイクルを確認

1. RHEL別の提供バージョン確認

OSバージョン無指定時AppStreamで提供されるバージョン提供形態
RHEL 8 PostgreSQL 10の既定ストリーム 9.6、10、12（RHEL 8.1.1以降）、13（RHEL 8.4以降）、15（RHEL 8.8以降）、16（RHEL 8.10以降） すべてモジュールストリーム
RHEL 9 PostgreSQL 13の非モジュールRPM 15（RHEL 9.2以降）、16（RHEL 9.4以降）、18（RHEL 9.8以降） 13はRPM、15・16・18はモジュールストリーム

RHEL 8のバージョン無指定時に選択されるPostgreSQL 10はApplication Streamのサポートが終了しているため、新規構築ではサポート期間とアプリケーション互換性を確認してストリームを明示

2026年8月時点でRHEL 8のPostgreSQL 9.6、10、13はサポート終了、12はRHEL 8のライフサイクルに追従、15は2028年5月、16は2029年5月までの提供予定

出典：Red Hat Enterprise Linux 8 - Database servers

出典：Red Hat Enterprise Linux 9 - Using PostgreSQL

出典：Red Hat Enterprise Linux Application Streams Life Cycle

2. インストールと初期化

2.1 OSとモジュールの確認

RHELリリースの確認

shell
cat /etc/redhat-release

PostgreSQLモジュールストリームの確認

shell
dnf module list postgresql

PostgreSQL関連の既存パッケージ確認

shell
rpm -qa | grep -E '^(postgresql|libpq)'

2.2 バージョン無指定でのサーバーインストール

RHEL 8の既定ストリームとserverプロファイルのインストール

RHEL 8
dnf module install postgresql/server

RHEL 9の非モジュールRPM版のインストール

RHEL 9
dnf install postgresql-server

2.3 バージョン指定でのサーバーインストール

RHEL 8またはRHEL 9で利用可能なストリームとserverプロファイルの指定

shell
dnf module install postgresql:<STREAM>/server

2.4 データベースクラスタの初期化

shell
postgresql-setup --initdb

2.5 サービスの有効化と起動

shell
systemctl enable --now postgresql.service

PostgreSQLサービス状態の確認

shell
systemctl status postgresql.service --no-pager

PostgreSQLの接続受付状態の確認

shell
pg_isready

サーバーバージョンの確認

shell
runuser -u postgres -- psql -c 'SELECT version();'

3. 設定ファイルと反映方法

パス用途
/var/lib/pgsql/data/postgresql.conf待受、メモリー、ログ、パスワード暗号化などのクラスタ設定
/var/lib/pgsql/data/postgresql.auto.confALTER SYSTEMが管理する設定であり、手動編集しない
/var/lib/pgsql/data/pg_hba.conf接続元、データベース、ロール、認証方式を上から順に評価
/var/lib/pgsql/data/pg_ident.confOSユーザーなどの外部IDとPostgreSQLロールの対応付け

3.1 実際の設定ファイルパスの確認

PostgreSQL管理者としてpsqlへ接続し、次のSQLを個別に実行

shell
runuser -u postgres -- psql
SQL
SHOW data_directory;
SQL
SHOW config_file;
SQL
SHOW hba_file;
SQL
SHOW ident_file;

3.2 設定ファイルのバックアップ

shell
cp -p /var/lib/pgsql/data/postgresql.conf /var/lib/pgsql/data/postgresql.conf.bak
shell
cp -p /var/lib/pgsql/data/pg_hba.conf /var/lib/pgsql/data/pg_hba.conf.bak

3.3 サーバー設定の編集

shell
vi /var/lib/pgsql/data/postgresql.conf
postgresql.conf
listen_addresses = '<DB_SERVER_PRIVATE_IP>'
port = <DB_PORT>
max_connections = <MAX_CONNECTIONS>
password_encryption = 'scram-sha-256'
log_connections = on

既定ポートを使用する場合は<DB_PORT>を5432へ置換し、後述するSELinux、firewalld、接続コマンドにも同じ値を使用

3.4 クライアント認証設定の編集

shell
vi /var/lib/pgsql/data/pg_hba.conf
pg_hba.conf
host    <APP_DATABASE>    <APP_ROLE>    <APP_SERVER_CIDR>    scram-sha-256

TLSを構成した接続だけを許可する場合はhostをhostsslへ変更し、サーバー証明書と秘密鍵を別途設定

書籍で使用されるmd5は新規設定へ採用せず、パスワード保存とHBA認証をscram-sha-256へ統一

3.5 設定ファイルの解析エラー確認

SQL
SELECT sourcefile, sourceline, error FROM pg_file_settings WHERE error IS NOT NULL;
SQL
SELECT line_number, type, database, user_name, address, auth_method, error FROM pg_hba_file_rules WHERE error IS NOT NULL;

3.6 設定の反映

pg_hba.confやSIGHUPで反映できる設定の再読み込み

SQL
SELECT pg_reload_conf();

listen_addressesやmax_connectionsなど再起動が必要な設定の反映

shell
systemctl restart postgresql.service

設定ごとの反映状態と再起動要否の確認

SQL
SELECT name,setting,context,source,sourcefile,pending_restart FROM pg_settings WHERE name IN ('listen_addresses','port','max_connections','password_encryption');

4. ポートとリモート接続設定

既定ポート5432を使用する場合、SELinuxのポート登録変更は不要

4.1 カスタムポート使用時のSELinuxツール導入

shell
dnf install policycoreutils-python-utils

4.2 カスタムポートのSELinux登録

現在のPostgreSQL用ポート登録の確認

shell
semanage port -l | grep postgresql_port_t

未登録のカスタムポート追加

shell
semanage port -a -t postgresql_port_t -p tcp <DB_PORT>

同じポートに別のSELinuxタイプが登録済みの場合は、追加ではなく-mによる変更可否を確認

4.3 接続元を限定したfirewalld設定

有効ゾーンの確認

shell
firewall-cmd --get-active-zones

有効ゾーンにおける接続元CIDRとDBポートの許可

shell
firewall-cmd --permanent --zone=<ACTIVE_ZONE> --add-rich-rule='rule family="ipv4" source address="<APP_SERVER_CIDR>" port protocol="tcp" port="<DB_PORT>" accept'

firewalld設定の再読み込み

shell
firewall-cmd --reload

PostgreSQLの待受確認

shell
ss -lntp | grep ':<DB_PORT>'

5. データベースとロールの作成

PostgreSQL管理コンソールへの接続

shell
runuser -u postgres -- psql

ログイン可能なアプリケーションロールの作成

SQL
CREATE ROLE <APP_ROLE> LOGIN;

パスワードを平文のSQLやシェル履歴へ残さない対話設定

psql
\password <APP_ROLE>

アプリケーションロールを所有者とするデータベースの作成

SQL
CREATE DATABASE <APP_DATABASE> OWNER <APP_ROLE>;

既定でPUBLICへ付与されるデータベース接続権限の削除

SQL
REVOKE CONNECT ON DATABASE <APP_DATABASE> FROM PUBLIC;
ℹ️ 権限の範囲

データベース所有者の<APP_ROLE>は接続とオブジェクト管理を行える。所有者とログインロールを分離する場合は、ログインロールへCONNECTを明示的に付与

データベースへのCONNECT権限は、スキーマ、テーブル、シーケンスの操作権限を自動付与しないため、オブジェクト所有者とアプリケーション要件に合わせて最小権限を追加

6. psql版別のロール確認

メタコマンドの仕様は接続先サーバーではなく、操作に使用するpsqlクライアントの版に依存

psqlクライアントバージョンの確認

shell
psql --version
psql版ロール一覧と属性ロール所属・付与関係
15以前\duまたは\dg\duのMember of列
16以降\duまたは\dg\drg

ロールと属性の一覧確認

psql
\du

psql 16以降におけるロール所属関係の確認

psql 16+
\drg

psql 16以降でシステムロールを含めた確認

psql 16+
\drgS
ℹ️ \drgの構文

変更点はPostgreSQL 15ではなくpsql 16で導入され、\du自体は16以降もロール一覧用として継続

\drg*や\drg+は正式な修飾形ではない。全件は\drg、システムロール込みは\drgSを使用し、*を使う場合は空白に続くロールパターンとして指定

出典：PostgreSQL 16 Release Notes

出典：PostgreSQL 16 - psql \drg

7. クライアントのインストールと更新

7.1 バージョン無指定でのクライアントインストール

RHEL 8の既定ストリームからclientプロファイルをインストール

RHEL 8
dnf module install postgresql/client

RHEL 9の非モジュールRPM版クライアントをインストール

RHEL 9
dnf install postgresql

7.2 バージョン指定でのクライアントインストール

shell
dnf module install postgresql:<STREAM>/client

7.3 現在のストリーム内でのクライアント更新

shell
dnf upgrade postgresql libpq

更新後のクライアントバージョン確認

shell
psql --version

リモートPostgreSQLへの接続確認

shell
psql --host=<DB_HOST> --port=<DB_PORT> --username=<APP_ROLE> --dbname=<APP_DATABASE>
⚠️ クライアントのメジャー版変更

通常のdnf upgradeは別のPostgreSQLストリームへ自動移行しない

クライアント専用ホストでは対象ストリームのclientプロファイルへ切り替えられるが、同一ホストにサーバーパッケージやPGDATAがある場合はDB本体のメジャーアップグレード手順を適用

8. バックアップと復元

8.1 バックアップ用ディレクトリの作成

shell
install -d -o postgres -g postgres -m 0700 /var/lib/pgsql/backups

8.2 グローバルオブジェクトのバックアップ

shell
runuser -u postgres -- pg_dumpall --globals-only --file=/var/lib/pgsql/backups/globals.sql

8.3 カスタム形式でのデータベースバックアップ

shell
runuser -u postgres -- pg_dump --format=custom --file=/var/lib/pgsql/backups/<APP_DATABASE>.dump <APP_DATABASE>

8.4 グローバルオブジェクトの復元

ロールと表領域をデータベース本体より先に復元

shell
runuser -u postgres -- psql --file=/var/lib/pgsql/backups/globals.sql postgres

8.5 復元先データベースの作成

shell
runuser -u postgres -- createdb --owner=<APP_ROLE> <RESTORE_DATABASE>

8.6 カスタム形式バックアップの復元

shell
runuser -u postgres -- pg_restore --dbname=<RESTORE_DATABASE> /var/lib/pgsql/backups/<APP_DATABASE>.dump
⚠️ バックアップの範囲

単一DBのpg_dumpにはロールや表領域などのグローバルオブジェクトが含まれないため、pg_dumpall --globals-onlyと設定ファイルも別途保全

復元先でデータ件数、所有者、権限、拡張、アプリケーション接続を確認

9. 更新と日常確認

現在選択中のストリーム内におけるPostgreSQLパッケージ更新

shell
dnf upgrade 'postgresql*' libpq
確認対象確認方法
サービスsystemctl status postgresql.service --no-pager
接続受付pg_isreadyと設定したDBポートの待受を確認
設定pg_settings、pg_file_settings、pg_hba_file_rulesを確認
接続アプリケーションロールと許可済み接続元から接続
ログjournalctl -u postgresql.service -bとPostgreSQLログを確認
容量/var/lib/pgsql/dataのファイルシステム容量とinodeを確認
復元性別環境への復元とアプリケーション疎通を確認

メジャーストリーム変更ではパッケージ切り替えだけでなく、バックアップと復元またはpg_upgradeによるデータ移行が必要

旧バージョンの設定ファイルを丸ごと上書きせず、新バージョンの既定値と廃止パラメータを確認して必要な設定だけを移植
