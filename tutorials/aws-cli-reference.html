AWS CLI コマンドリファレンス

AWS CLIでVPCからEC2、Application Load Balancerまでを構築する流れと、IAM、Security Group、Prefix List、SNSなどの日常運用コマンドを整理する

AWS CLIによるVPC／EC2／ALB構築フロー

AWS CLIでネットワークから仮想サーバー、ロードバランサーまでを順に構築する

VPC → サブネット → ルートテーブル → インターネットゲートウェイ → デフォルトルート
キーペア → Security Group → EC2 → AMI → EIP
ターゲットグループ → EC2インスタンス登録 → Application Load Balancer（リスナー作成）

1. VPCの作成

CIDRブロック 10.0.0.0/16 のVPCを作成し、DNSホスト名を有効化する

AWS CLI
aws ec2 create-vpc --cidr-block 10.0.0.0/16
aws ec2 modify-vpc-attribute \
  --vpc-id <VPC_ID> \
  --enable-dns-hostnames Value=true

専用テナンシーを指定してVPCを作成する場合

AWS CLI
aws ec2 create-vpc --cidr-block 10.0.0.0/16 --instance-tenancy dedicated

2. サブネットの作成

異なるアベイラビリティーゾーンへ2つのサブネットを作成する

AWS CLI
aws ec2 create-subnet \
  --vpc-id <VPC_ID> \
  --availability-zone ap-northeast-1a \
  --cidr-block 10.0.0.0/24
aws ec2 create-subnet \
  --vpc-id <VPC_ID> \
  --availability-zone ap-northeast-1c \
  --cidr-block 10.0.100.0/24

3. ルートテーブルの作成と関連付け

ルートテーブルを作成し、サブネットへ関連付ける

AWS CLI
aws ec2 create-route-table --vpc-id <VPC_ID>
aws ec2 associate-route-table \
  --route-table-id <ROUTE_TABLE_ID> \
  --subnet-id <SUBNET_ID>

4. インターネットゲートウェイの作成

インターネットゲートウェイを作成し、VPCへアタッチする

AWS CLI
aws ec2 create-internet-gateway
aws ec2 attach-internet-gateway \
  --internet-gateway-id <INTERNET_GATEWAY_ID> \
  --vpc-id <VPC_ID>

5. デフォルトルートの作成

宛先 0.0.0.0/0 をインターネットゲートウェイへ向ける

AWS CLI
aws ec2 create-route \
  --route-table-id <ROUTE_TABLE_ID> \
  --destination-cidr-block 0.0.0.0/0 \
  --gateway-id <INTERNET_GATEWAY_ID>

6. キーペアの作成と公開鍵のインポート

キーペアを作成する

AWS CLI
aws ec2 create-key-pair --key-name myKeyPair

秘密鍵を myKeyPair.pem へ保存する場合

AWS CLI
aws ec2 create-key-pair \
  --key-name myKeyPair \
  --query 'KeyMaterial' \
  --output text > myKeyPair.pem

既存の公開鍵をインポートする場合

AWS CLI
aws ec2 import-key-pair \
  --key-name ImportKey \
  --public-key-material fileb://~/.ssh/id_rsa.pub

7. Security Groupの作成

Security Groupを作成し、接続元グローバルIPv4アドレスからのSSHを許可して設定を確認する

AWS CLI
aws ec2 create-security-group \
  --group-name mySecurityGroup \
  --description "my First Security Group" \
  --vpc-id <VPC_ID>
AWS CLI
aws ec2 authorize-security-group-ingress \
  --group-id <SECURITY_GROUP_ID> \
  --protocol tcp \
  --port 22 \
  --cidr <GLOBAL_IPV4_ADDRESS>/32
aws ec2 describe-security-groups \
  --group-ids <SECURITY_GROUP_ID> \
  --output json

8. EC2インスタンスの作成

AMI、インスタンスタイプ、キーペア、Security Group、サブネットを指定してEC2インスタンスを起動し、Nameタグを追加する

AWS CLI
aws ec2 run-instances \
  --image-id <AMI_ID> \
  --count 1 \
  --instance-type t3.micro \
  --key-name myKeyPair \
  --security-group-ids <SECURITY_GROUP_ID> \
  --subnet-id <SUBNET_ID>
AWS CLI
aws ec2 create-tags \
  --resources <INSTANCE_ID> \
  --tags Key=Name,Value=myFirstEC2

9. AMIの作成と確認

EC2インスタンスからAMIを作成し、AMI IDを指定して確認する

AWS CLI
aws ec2 create-image \
  --instance-id <INSTANCE_ID> \
  --name "myFirstEC2" \
  --description "myFirstEC2-AMI"
AWS CLI
aws ec2 describe-images --image-ids <AMI_ID>

10. Elastic IPの取得と関連付け

VPC用のElastic IPを取得し、EC2インスタンスへ関連付けて確認する

AWS CLI
aws ec2 allocate-address --domain vpc
aws ec2 associate-address \
  --instance-id <INSTANCE_ID> \
  --allocation-id <ALLOCATION_ID>
aws ec2 describe-addresses

11. Application Load Balancerの作成とEC2インスタンスの登録

2つのアベイラビリティーゾーンへインターネット向けApplication Load Balancerを作成し、実行結果のARNを控える

AWS CLI
aws elbv2 create-load-balancer \
  --name External-Web \
  --type application \
  --scheme internet-facing \
  --ip-address-type ipv4 \
  --tags Key=Name,Value=External-Web \
  --subnets <SUBNET_ID_1> <SUBNET_ID_2> \
  --security-groups <ALB_SECURITY_GROUP_ID> \
  --query 'LoadBalancers[0].LoadBalancerArn' \
  --output text

HTTPの80番ポートを使用するインスタンスターゲットグループを作成し、実行結果のARNを控える

AWS CLI
aws elbv2 create-target-group \
  --name External-Web-TG \
  --protocol HTTP \
  --port 80 \
  --vpc-id <VPC_ID> \
  --target-type instance \
  --query 'TargetGroups[0].TargetGroupArn' \
  --output text

2台のEC2インスタンスをターゲットグループへ登録する

AWS CLI
aws elbv2 register-targets \
  --target-group-arn <TARGET_GROUP_ARN> \
  --targets Id=<INSTANCE_ID_1> Id=<INSTANCE_ID_2>

Application Load BalancerにHTTPリスナーを作成し、受信した通信をターゲットグループへ転送する

AWS CLI
aws elbv2 create-listener \
  --load-balancer-arn <LOAD_BALANCER_ARN> \
  --protocol HTTP \
  --port 80 \
  --default-actions Type=forward,TargetGroupArn=<TARGET_GROUP_ARN>

出典：Create an Application Load Balancer

認証情報の確認

現在の認証情報が、想定しているAWSアカウントとIAMユーザー/ロールを向いているか確認する

CloudShell
aws sts get-caller-identity

認証情報の設定

作業端末で初めてAWS CLIを使う場合は、デフォルト認証情報を設定する

CloudShell
aws configure
ℹ️ 情報

--profileは、複数のAWSアカウントやIAMユーザーを名前付きプロファイルで切り替える場合だけ指定する
このページでは、デフォルト認証情報を使う前提で記載する

リージョンの設定と確認

以降のコマンドを実行するAWSリージョンを、名前付きプロファイルまたはデフォルト設定へ登録する

値説明
<REGION>作業対象のAWSリージョン
例: ap-northeast-1

作業対象のリージョンを設定する

CloudShell
aws configure set region <REGION>

設定したリージョンを確認する

CloudShell
aws configure get region

Identity and Access Management (IAM)

人がAWSへログインする用途では、AWS IAM Identity Centerによる一時的な認証情報の利用を優先する
このセクションでは、個別要件によりIAMユーザー、IAMグループ、IAMポリシー、アクセスキー、コンソールログインをAWS CLIで管理する場合の基本操作を整理する

出典：Create an IAM user in your AWS account

値説明
<USER_NAME>作成または確認するIAMユーザー名
<GROUP_NAME>ユーザーを所属させるIAMグループ名
<POLICY_NAME>作成するカスタマー管理ポリシー名
<CUSTOM_POLICY_ARN>作成済みカスタマー管理ポリシーのARN

IAMユーザーを作成する

CloudShell
aws iam create-user --user-name <USER_NAME>

IAMグループを作成する

CloudShell
aws iam create-group --group-name <GROUP_NAME>

作成したIAMユーザーを既存グループに追加する

CloudShell
aws iam add-user-to-group --user-name <USER_NAME> --group-name <GROUP_NAME>

AWS管理ポリシーをIAMグループにアタッチする
例では読み取り専用のReadOnlyAccessを使用する

CloudShell
aws iam attach-group-policy --group-name <GROUP_NAME> --policy-arn arn:aws:iam::aws:policy/ReadOnlyAccess

カスタマー管理ポリシーを作成する場合は、ポリシードキュメントをJSONで用意する

json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ec2:Describe*"
      ],
      "Resource": "*"
    }
  ]
}

JSONファイルからカスタマー管理ポリシーを作成する

CloudShell
aws iam create-policy --policy-name <POLICY_NAME> --policy-document file://policy.json

作成したカスタマー管理ポリシーをIAMグループにアタッチする

CloudShell
aws iam attach-group-policy --group-name <GROUP_NAME> --policy-arn <CUSTOM_POLICY_ARN>

IAMグループにアタッチされているポリシーを確認する

CloudShell
aws iam list-attached-group-policies --group-name <GROUP_NAME>

ユーザーの所属グループを確認する

CloudShell
aws iam list-groups-for-user --user-name <USER_NAME>

IAMユーザーのアクセスキーを発行する

CloudShell
aws iam create-access-key --user-name <USER_NAME>
⚠️ 注意

AWS CLIでアクセスキーを発行しても、CSVファイルは自動ダウンロードされない
AccessKeyIdとSecretAccessKeyは実行結果に表示される
SecretAccessKeyは作成時にだけ取得できるため、必要な場合は安全な場所へ即時保管する

出典：create-access-key

CloudShellで一時パスワードを自動生成する

CloudShell
TEMPORARY_PASSWORD="$(openssl rand -base64 32 | tr -dc 'A-Za-z0-9' | head -c 20)Aa1-"

生成した一時パスワードを使用して、IAMユーザーへコンソールログイン用のログインプロファイルを作成する

CloudShell
aws iam create-login-profile --user-name <USER_NAME> --password "$TEMPORARY_PASSWORD" --password-reset-required

AWSアカウントIDを取得する

CloudShell
ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"

コンソールサインインURL、IAMユーザー名、一時パスワードを画面へ一度だけ表示する

CloudShell
printf 'URL: https://%s.signin.aws.amazon.com/console/\nUser: %s\nPassword: %s\n' "$ACCOUNT_ID" '<USER_NAME>' "$TEMPORARY_PASSWORD"

利用者へ安全に共有した後、一時パスワードをシェル変数から削除する

CloudShell
unset TEMPORARY_PASSWORD
ℹ️ 情報

AWS CLIのcreate-login-profileは一時パスワードを自動生成しないため、CloudShellなど実行環境側で生成して指定する
create-login-profileの実行結果には、IAMユーザー名、作成日時、初回変更の要否が表示され、指定したパスワードとコンソールサインインURLは表示されない
マネジメントコンソールのような認証情報CSVは作成されないため、必要な情報を安全な経路で利用者へ共有する

出典：create-login-profile
出典：How IAM users sign in to AWS

IAMユーザーの利用停止・削除

異動、退職、アカウント整理に伴いIAMユーザーを停止する場合は、削除前にアクセスキーとコンソールログインを無効化し、依存する処理への影響を確認する
人のログイン用途ではAWS IAM Identity Centerを優先し、IAMユーザーはサービス要件がある場合に限定する

値説明
<USER_NAME>利用停止または削除するIAMユーザー名
<ACCESS_KEY_ID>無効化するアクセスキーID

アクセスキーを確認して無効化する

CloudShell
aws iam list-access-keys --user-name <USER_NAME>
aws iam update-access-key --user-name <USER_NAME> --access-key-id <ACCESS_KEY_ID> --status Inactive

コンソールログインを停止する

CloudShell
aws iam delete-login-profile --user-name <USER_NAME>

IAMユーザーを完全に削除する場合は、アクセスキー、グループ所属、MFAデバイス、ポリシーなどの依存関係を先に解除してからdelete-userを実行する

Security Group ルール追加・削除

Security Groupルールを変更する前に、対象Security Group、方向、プロトコル、ポート、送信元または送信先、説明を確定する
すべてのプロトコルを指定する場合は、--protocol -1を使用する

出典：authorize-security-group-ingress

値説明
<SECURITY_GROUP_ID>変更対象のSecurity Group ID
<CIDR>許可または削除する送信元CIDR
例: 203.0.113.10/32
<DESCRIPTION>Security Groupルールの説明
例: office-a temporary access

作業前に、対象Security Groupの現在のルールを確認する

CloudShell
aws ec2 describe-security-groups --group-ids <SECURITY_GROUP_ID>

ケース①：特定のCIDRからHTTP（80/tcp）への接続だけを許可する

CloudShell
aws ec2 authorize-security-group-ingress --group-id <SECURITY_GROUP_ID> --protocol tcp --port 80 --cidr <CIDR>

ケース②：特定のCIDRからHTTP（80/tcp）への接続を、説明付きで許可する

CloudShell
aws ec2 authorize-security-group-ingress --group-id <SECURITY_GROUP_ID> --ip-permissions 'IpProtocol=tcp,FromPort=80,ToPort=80,IpRanges=[{CidrIp=<CIDR>,Description="<DESCRIPTION>"}]'

ケース③：特定のCIDRから全プロトコル・全ポートへの接続を一時的に許可する

CloudShell
aws ec2 authorize-security-group-ingress --group-id <SECURITY_GROUP_ID> --protocol -1 --cidr <CIDR>

Security GroupルールID、CIDR、説明欄を一覧で確認する

CloudShell
aws ec2 describe-security-group-rules --filters Name=group-id,Values=<SECURITY_GROUP_ID> --query "SecurityGroupRules[*].[SecurityGroupRuleId,IsEgress,IpProtocol,FromPort,ToPort,CidrIpv4,Description]" --output table

ケース①で追加したHTTP（80/tcp）の許可ルールを削除する

CloudShell
aws ec2 revoke-security-group-ingress --group-id <SECURITY_GROUP_ID> --protocol tcp --port 80 --cidr <CIDR>

ケース③で追加した全プロトコル・全ポートの許可ルールを削除する

CloudShell
aws ec2 revoke-security-group-ingress --group-id <SECURITY_GROUP_ID> --protocol -1 --cidr <CIDR>

Prefix Listの作成・IP登録

複数の接続元CIDRをCustomer-managed Prefix Listへ集約し、Security Groupから1つの参照として利用する
接続元の追加・削除をPrefix List側で管理できるため、同じCIDR一覧を複数のSecurity Groupで利用する構成に適している

出典：Managed prefix lists

⚠️ 注意

Security GroupからPrefix Listを1件参照する場合も、クォータではPrefix Listの最大エントリ数分のルールとして扱われる
<MAX_ENTRIES>は将来の追加分を考慮しつつ、必要以上に大きく設定しない

入力値

値説明
<PREFIX_LIST_NAME>作成または更新するPrefix List名
<MAX_ENTRIES>Prefix Listに登録できる最大エントリ数
例: 10
<CIDR_1>登録する接続元CIDR
例: 203.0.113.10/32
<CIDR_2>作成時に追加で登録する接続元CIDR
1件だけ登録する場合は指定不要
<CIDR_3>作成後に追加する接続元CIDR
<DESCRIPTION_1>登録CIDRの説明
例: office-a
<DESCRIPTION_2><CIDR_2>の説明
<DESCRIPTION_3><CIDR_3>の説明
<PREFIX_LIST_ID>作成後に払い出されるPrefix List ID
<CURRENT_VERSION>更新前に確認した現在のバージョン
<SECURITY_GROUP_ID>Prefix Listを参照させるSecurity Group ID
<PORT>許可するポート番号
例: 443

Prefix Listの作成

Prefix Listを作成し、初期CIDRを登録する
接続元を1件だけ登録する場合は、Cidr=<CIDR_2>,Description="<DESCRIPTION_2>"をコマンドから削除する

CloudShell
aws ec2 create-managed-prefix-list --prefix-list-name <PREFIX_LIST_NAME> --address-family IPv4 --max-entries <MAX_ENTRIES> --entries Cidr=<CIDR_1>,Description="<DESCRIPTION_1>" Cidr=<CIDR_2>,Description="<DESCRIPTION_2>"

Prefix Listの確認・更新

作成したPrefix ListのID、現在のバージョン、最大エントリ数、状態を確認する

CloudShell
aws ec2 describe-managed-prefix-lists --filters Name=prefix-list-name,Values=<PREFIX_LIST_NAME> --query "PrefixLists[*].[PrefixListId,PrefixListName,Version,MaxEntries,State]" --output table

既存のPrefix Listへ接続元CIDRを追加する
直前に確認したVersionを<CURRENT_VERSION>へ指定する

CloudShell
aws ec2 modify-managed-prefix-list --prefix-list-id <PREFIX_LIST_ID> --current-version <CURRENT_VERSION> --add-entries Cidr=<CIDR_3>,Description="<DESCRIPTION_3>"

更新後に、Prefix Listへ登録されているCIDRと説明を確認する

CloudShell
aws ec2 get-managed-prefix-list-entries --prefix-list-id <PREFIX_LIST_ID> --query "Entries[*].[Cidr,Description]" --output table

Security Groupからの参照

Security GroupのインバウンドルールからPrefix Listを参照する
Prefix Listへ登録した接続元CIDR群から<PORT>へのTCP通信を許可する

CloudShell
aws ec2 authorize-security-group-ingress --group-id <SECURITY_GROUP_ID> --ip-permissions IpProtocol=tcp,FromPort=<PORT>,ToPort=<PORT>,PrefixListIds=[{PrefixListId=<PREFIX_LIST_ID>}]

SNS Topic・Subscription作成

通知先を作成する場合は、Topic、Subscription、確認メールの承認、通知テスト、設定確認、不要時の解除までを一連の手順として扱う

出典：subscribe

値説明
<TOPIC_NAME>作成するSNS Topic名
<TOPIC_ARN>作成済みSNS TopicのARN
<MAIL_ADDRESS>通知先メールアドレス
<SUBSCRIPTION_ARN>SubscriptionのARN
承認前はPendingConfirmationになる

SNS Topicを作成する

CloudShell
aws sns create-topic --name <TOPIC_NAME>

SNS Topic一覧を確認する

CloudShell
aws sns list-topics

メール通知先をSubscriptionとして登録する

CloudShell
aws sns subscribe --topic-arn <TOPIC_ARN> --protocol email --notification-endpoint <MAIL_ADDRESS>
ℹ️ 情報

emailプロトコルのSubscriptionは、通知先に届く確認メールを承認するまで配信されない
承認前はSubscription ARNがPendingConfirmationと表示される

Topicに紐づくSubscriptionを確認する

CloudShell
aws sns list-subscriptions-by-topic --topic-arn <TOPIC_ARN>

Topic属性を確認する

CloudShell
aws sns get-topic-attributes --topic-arn <TOPIC_ARN>

通知テストを実行する

CloudShell
aws sns publish --topic-arn <TOPIC_ARN> --message "notification test"

不要になったSubscriptionを解除する

CloudShell
aws sns unsubscribe --subscription-arn <SUBSCRIPTION_ARN>

EC2 / EBS ボリューム拡張

ファイルシステムの空き容量が不足した場合は、Elastic Volumesを使用してEBSボリュームをオンラインで拡張する
作業前にスナップショットを取得して必要なサイズを確定し、変更後にOS側のパーティションとファイルシステムを拡張する

出典：Modify an Amazon EBS volume using Elastic Volumes operations

値説明
<VOLUME_ID>拡張するEBSボリュームID
<TARGET_SIZE_GIB>拡張後のサイズ（GiB）
現在のサイズ以上を指定

作業前の復旧ポイントとしてスナップショットを作成

CloudShell
aws ec2 create-snapshot --volume-id <VOLUME_ID> --description "pre-resize backup"

権限と入力値を事前確認する
DryRunOperationが返る場合は実行権限がある

CloudShell
aws ec2 modify-volume --volume-id <VOLUME_ID> --size <TARGET_SIZE_GIB> --dry-run

EBSボリュームの拡張

CloudShell
aws ec2 modify-volume --volume-id <VOLUME_ID> --size <TARGET_SIZE_GIB>

変更状況を確認する
OS側の拡張は、状態がoptimizingまたはcompletedになってから実施する

CloudShell
aws ec2 describe-volumes-modifications --volume-ids <VOLUME_ID> --query "VolumesModifications[*].[VolumeId,ModificationState,OriginalSize,TargetSize,Progress]" --output table
⚠️ 注意

Amazon EBSの仕様では、ボリュームサイズを拡張できるが、縮小はサポートされていない
OS側の拡張前に、対象デバイス名、パーティション、ファイルシステムの種類を確認する
既存データを保持するボリュームを再フォーマットするとデータが削除されるため、ファイルシステム作成コマンドを実行しない

出典：Extend the file system after resizing an Amazon EBS volume
出典：Make an Amazon EBS volume available for use

AWS WAF IPセットの更新

接続元IPアドレスの追加または削除が発生する場合は、Web ACLに関連付けたIPセットを更新する
変更前に現在のアドレスとロックトークンを取得し、更新後も保持するすべてのアドレスを指定する

出典：update-ip-set

値説明
<IP_SET_NAME>更新対象のAWS WAF IPセット名
<IP_SET_ID>更新対象のIPセットID
<SCOPE>REGIONAL または CLOUDFRONT
<LOCK_TOKEN>取得直後のIPセット状態を示すロックトークン

現在のアドレスとロックトークンを取得する
CloudFrontスコープの場合は--region us-east-1を追加する

CloudShell
aws wafv2 get-ip-set --name <IP_SET_NAME> --scope <SCOPE> --id <IP_SET_ID>

更新後のアドレス一覧を作成する
既存アドレスを残す場合は、必ず同じファイルへ含める

json
[
  "203.0.113.10/32",
  "198.51.100.0/24"
]

IPセットの更新

CloudShell
aws wafv2 update-ip-set --name <IP_SET_NAME> --scope <SCOPE> --id <IP_SET_ID> --lock-token <LOCK_TOKEN> --addresses file://ip-set-addresses.json
⚠️ 注意

update-ip-setは指定したアドレス一覧でIPセット全体を置き換える
既存アドレスをJSONファイルから省くと、そのアドレスは削除される
更新競合時は新しいロックトークンを取得し直して内容を再確認する
