Redis（KVS）

⚡ このページの要約

RHEL 9へRedisを導入し、待受、認証、データ永続化、バックアップを構成する
レプリケーションとSentinelによる監視・自動フェイルオーバーの基本手順をまとめる

1. 構成パラメータの確認

Redisを外部へ公開する場合は、待受アドレス、接続元、認証、暗号化、容量上限、永続化方式を事前に定義する

項目パラメータ
待受アドレス<REDIS_LISTEN_ADDRESS>
Redisポート6379/TCP
Sentinelポート26379/TCP
許可する接続元<REDIS_CLIENT_CIDR>
認証情報設定管理システムまたは権限制限済みファイルで管理
永続化RDB、AOF、または両方
⚠️ インターネット公開禁止

Redisの6379/TCPとSentinelの26379/TCPを不特定の接続元へ公開しない。Security Group、firewalld、Redis ACLを重ねて制御する

2. インストールと起動

2.1 パッケージ情報の確認

user shell
dnf info redis

2.2 Redisのインストール

root shell
dnf install redis

2.3 バージョンの確認

user shell
redis-server --version
rpm -q redis

2.4 サービスの有効化

root shell
systemctl enable --now redis

3. 待受・認証・メモリ設定

標準設定をバックアップし、環境固有の値だけを変更する。パスワードやACLパスワードはページ、チケット、シェル履歴へ記録しない

3.1 設定ファイルのバックアップ

root shell
cp -pi /etc/redis/redis.conf /etc/redis/redis.conf.$(date +%Y%m%d)

3.2 設定ファイルの編集

root shell
vi /etc/redis/redis.conf
redis.conf
bind 127.0.0.1 <REDIS_LISTEN_ADDRESS>
protected-mode yes
port 6379
supervised systemd
maxmemory <MAX_MEMORY>
maxmemory-policy allkeys-lru

user default off
user <REDIS_USER> on ><REDIS_PASSWORD> ~* +@all
user <REPLICATION_USER> on ><REPLICATION_PASSWORD> +psync +replconf +ping
user <SENTINEL_REDIS_USER> on ><SENTINEL_REDIS_PASSWORD> resetchannels &__sentinel__:hello +multi +slaveof +ping +exec +subscribe +config|rewrite +role +publish +info +client|setname +client|kill +script|kill

アプリケーションの用途に応じ、~*のキーパターンと+@allのコマンド権限を必要最小限へ絞る

3.3 SELinuxコンテキストと設定差分の確認

root shell
restorecon -v /etc/redis/redis.conf
diff -u /etc/redis/redis.conf.$(date +%Y%m%d) /etc/redis/redis.conf

3.4 設定反映と状態確認

root shell
systemctl restart redis
systemctl status redis --no-pager
ss -lntp | grep ':6379'

4. 接続元の制限

firewalldが有効な環境では、接続元を限定したrich ruleでRedisポートを許可する

4.1 firewalldの状態確認

user shell
systemctl is-active firewalld

4.2 接続元を限定した許可

root shell
firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="<REDIS_CLIENT_CIDR>" port port="6379" protocol="tcp" accept'
firewall-cmd --reload
firewall-cmd --list-rich-rules

5. 接続とデータ操作

--askpassを使用して認証情報を対話入力し、プロセス一覧とシェル履歴への露出を避ける

5.1 PINGによる接続確認

client shell
redis-cli -h <REDIS_SERVER> --user <REDIS_USER> --askpass PING

5.2 キーの登録・取得・削除

client shell
redis-cli -h <REDIS_SERVER> --user <REDIS_USER> --askpass SET <KEY> <VALUE>
redis-cli -h <REDIS_SERVER> --user <REDIS_USER> --askpass GET <KEY>
redis-cli -h <REDIS_SERVER> --user <REDIS_USER> --askpass DEL <KEY>

5.3 サーバー情報の確認

client shell
redis-cli -h <REDIS_SERVER> --user <REDIS_USER> --askpass INFO server
redis-cli -h <REDIS_SERVER> --user <REDIS_USER> --askpass INFO memory

6. 永続化とバックアップ

RDBは時点スナップショット、AOFは書き込み操作の追記を行う。復旧目標とI/O特性に応じて選択する

6.1 永続化設定の編集

root shell
vi /etc/redis/redis.conf
redis.conf
save 3600 1
save 300 100
save 60 10000
appendonly yes
appendfsync everysec

6.2 バックグラウンド保存の実行

client shell
redis-cli -h <REDIS_SERVER> --user <REDIS_USER> --askpass BGSAVE
redis-cli -h <REDIS_SERVER> --user <REDIS_USER> --askpass LASTSAVE

6.3 データディレクトリの確認

root shell
redis-cli --user <REDIS_USER> --askpass CONFIG GET dir
redis-cli --user <REDIS_USER> --askpass CONFIG GET dbfilename
ls -la /var/lib/redis
⚠️ バックアップ整合性

データファイルをコピーする前にBGSAVEの完了を確認する。復元手順は別環境で検証し、RDBまたはAOFの保管先をRedisサーバーと分離する

7. レプリケーションの構成

ReplicaはPrimaryからデータを複製する。書き込み先の自動切り替えにはSentinelまたはアプリケーション側の対応が必要になる

7.1 Replica設定の追加

replica redis.conf
replicaof <PRIMARY_ADDRESS> 6379
masteruser <REPLICATION_USER>
masterauth <REPLICATION_PASSWORD>
replica-read-only yes

7.2 Replicaサービスの再起動

replica root
systemctl restart redis

7.3 レプリケーション状態の確認

client shell
redis-cli -h <REDIS_SERVER> --user <REDIS_USER> --askpass INFO replication

8. Sentinelの構成

Sentinelを3台以上の奇数台で構成し、Primary監視とクォーラム判定を分散する

8.1 Sentinel設定ファイルのバックアップと編集

sentinel root
cp -pi /etc/redis/sentinel.conf /etc/redis/sentinel.conf.$(date +%Y%m%d)
vi /etc/redis/sentinel.conf
sentinel.conf
bind 127.0.0.1 <SENTINEL_LISTEN_ADDRESS>
protected-mode yes
port 26379
requirepass <SENTINEL_PASSWORD>
sentinel monitor <MASTER_NAME> <PRIMARY_ADDRESS> 6379 2
sentinel auth-user <MASTER_NAME> <SENTINEL_REDIS_USER>
sentinel auth-pass <MASTER_NAME> <SENTINEL_REDIS_PASSWORD>
sentinel down-after-milliseconds <MASTER_NAME> 5000
sentinel failover-timeout <MASTER_NAME> 60000

8.2 Sentinelの有効化

sentinel root
restorecon -v /etc/redis/sentinel.conf
systemctl enable --now redis-sentinel

8.3 Sentinel接続元の許可

sentinel root
firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="<SENTINEL_PEER_CIDR>" port port="26379" protocol="tcp" accept'
firewall-cmd --reload

8.4 Sentinel状態の確認

client shell
redis-cli -h <SENTINEL_SERVER> -p 26379 --askpass SENTINEL master <MASTER_NAME>
redis-cli -h <SENTINEL_SERVER> -p 26379 --askpass SENTINEL replicas <MASTER_NAME>

9. 運用確認

確認対象確認方法
サービスsystemctl status redis redis-sentinel
待受ss -lntpで6379と26379を確認
メモリINFO memoryとエビクション件数を監視
永続化INFO persistenceでRDBとAOFの状態を確認
複製INFO replicationでrole、link、offsetを確認
ログjournalctl -u redis -u redis-sentinelを確認

9.1 警告以上のログ確認

root shell
journalctl -u redis -u redis-sentinel -p warning..alert --since today
