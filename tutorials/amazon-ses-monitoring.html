Amazon SES 配信監視

Amazon SESの配信、バウンス、苦情、遅延を収集し、異常を通知する監視手順をまとめる
Configuration Setを起点としたSNS、EventBridge、CloudWatchの設定と、サプレッションリスト、VDM、送信クォータの確認方法を整理する

配信監視の全体像

SMTPサーバーでstatus=sentになっても、SESが受信者のメールサーバーへ配信したことまでは保証しない
PostfixからSESへの引き渡し、SESの配信イベント、受信者側の結果を分けて確認する

確認レイヤー確認内容主な確認先
PostfixSES SMTPエンドポイントへ引き渡せたかjournalctl、メールキュー
Amazon SESSend、Delivery、Bounce、Complaint、DeliveryDelayConfiguration Setのイベント送信先
通知即時通知、イベント振り分け、メトリクスアラームSNS、EventBridge、CloudWatch
レピュテーションバウンス率、苦情率、アカウント状態SESレピュテーションメトリクス
到達性ISP、送信ID、Configuration Set別の配信傾向Virtual Deliverability Manager
ℹ️ このページの検証構成

東京リージョン、Configuration Set名ses-postfix-monitoring、SNSトピック名ses-events-notificationを例にする
名前、ARN、送信ID、メールアドレスは環境に合わせて変更する

Configuration Setの作成

Configuration Setは、イベント送信先、レピュテーションメトリクス、VDM設定などを送信メールへまとめて適用する単位
同じ送信IDでも、トランザクションメールとマーケティングメールを分けると、監視と変更管理を独立させやすい

出典：Configuration Setの作成

  1. Amazon SESコンソールを東京リージョンで開き、設定 ＞ 設定セットを選択
  2. セットの作成を選択
  3. 全般的な詳細 ＞ 設定セット名へses-postfix-monitoringを入力
  4. IPプールを送信するは、専用IPプールを使用しない場合はdefaultを選択
  5. 次の表に従って各オプションを設定
  6. 必要に応じてタグを設定し、画面下部のセットの作成を選択
コンソールの項目今回の設定変更する場合
追跡オプション
カスタムリダイレクトドメインの使用		チェックしない独自ドメインで開封・クリック追跡を行う場合に設定
追跡イベントを収集するにはイベント送信先も必要
高度な配信オプション
Transport Layer Security (TLS)		必須をチェックしない受信側メールサーバーとTLS接続できない場合に配信を失敗させる要件があるときだけチェック
高度な配信オプション
最大配信期間 - オプション		空欄SESがメール配信を試行する最大時間を制限する要件がある場合に300～50,400秒で指定

Eメールをアーカイブ		有効化をチェックしないSES Mail Managerのアーカイブへ保存する場合に設定
テナント
テナントに割り当てる		チェックしないSESのマルチテナント機能を使用する場合に設定
ℹ️ 送信可否

現在のセットの作成画面に送信オプションという項目は表示されない
設定セットは送信可能な状態で作成され、停止する場合は作成後の設定セット詳細画面で送信を無効化を使用する

設定セット単位のサプレッションリスト上書き

サプレッションリストのオプション ＞ アカウントレベル設定を上書きするは、設定セットを使用したメールだけに独自の抑止条件を適用する項目
通常はチェックせず、アカウントレベルの設定を継承する

設定セットの指定送信時の動作用途
アカウントレベル設定を上書きするをチェックしないアカウントレベルのサプレッションリスト設定を使用今回の推奨設定
上書きをチェックし、設定セットのサプレッションリストを有効化しないアカウントレベルの設定を使用せず、この設定セットでは抑止条件を設定しない抑止を使用しない明確な要件がある場合のみ
上書きをチェックし、設定セットのサプレッションリストを有効化この設定セットで選択したBounce、Complaint、または両方を抑止理由として使用トランザクションメールとマーケティングメールで抑止理由を分ける場合
⚠️ サプレッションリストの上書き

上書きだけを有効にし、設定セット側のサプレッションリストを有効化しない構成では、アカウントレベルの抑止設定が使用されない
意図せず抑止を解除しないよう、上書きの有無と抑止理由を保存前に確認する

出典：設定セットレベルのサプレッションリスト

作成したConfiguration Setの設定を確認

CloudShell
aws sesv2 get-configuration-set \
  --configuration-set-name <CONFIGURATION_SET_NAME> \
  --region <REGION>

作成後は設定セットの概要を開き、評判オプション、サプレッションリスト、VDM、送信状態が意図した設定になっていることを確認する

イベント送信先の作成

Configuration Setのイベント送信先で、収集するイベントと出力先を設定する
1つのConfiguration Setには複数のイベント送信先を作成できるため、通知用SNS、振り分け用EventBridge、集計用CloudWatchを分けて設定する

出典：イベント送信先の作成

送信先向いている用途保持・確認方法
Amazon SNSバウンスや苦情をメール、SMS、Lambdaなどへ即時通知購読先へJSONイベントを配信
Amazon EventBridgeイベント種別で振り分け、SNS、SQS、Lambda、Step Functionsへ連携ルールのメトリクス、Target、DLQで確認
Amazon CloudWatchイベント件数をメトリクス化し、ダッシュボードとアラームで監視AWS/SESメトリクスで確認

イベントタイプの選択

イベントタイプの選択では、SESからイベント送信先へ発行する送信結果を選ぶ
今回の基本監視では送信、拒否、配信、ハードバウンス、苦情数、配信の遅延を選択し、利用している機能に応じて残りの項目を追加する

コンソールの項目今回の選択確認できること
送信選択送信リクエストが成功し、SESが受信者のメールサーバーへの配信処理を開始したこと
レンダリングの失敗テンプレート送信時に選択テンプレートデータの不足や不一致により、メールが送信されなかったこと
拒否選択SESがウイルスを含むと判断し、受信者のメールサーバーへ配信しなかったこと
配信選択SESが受信者のメールサーバーへ正常に引き渡したこと
受信トレイへの格納を保証するイベントではない
ハードバウンス選択受信者のメールサーバーが恒久的に拒否したこと
SESが再試行後に配信を終了したソフトバウンスも含む
苦情数選択配信後に受信者がスパムとして報告したこと
配信の遅延選択メールボックス容量不足や受信側サーバーの一時障害などにより、配信が遅延していること
サブスクリプションリスト管理使用時に選択受信者が購読解除ヘッダーまたはフッターから購読設定を変更したこと
開封数開封追跡時に選択受信者のメールクライアントでメッセージが開かれたこと
クリック数クリック追跡時に選択受信者がメール内のリンクをクリックしたこと

開封数とクリック数は、追跡によるURL書き換え、個人情報の取り扱い、セキュリティ製品による自動アクセスを確認したうえで選択する
すべて選択は、使用していない機能のイベントまで収集するため、検証目的が明確な場合だけ使用する

Amazon SNS

  1. Amazon SNSコンソールでトピック ＞ トピックの作成を選択
  2. タイプはスタンダード、名前はses-events-notificationとして作成
  3. サブスクリプションの作成で通知先メールアドレスを登録
  4. 届いた確認メールから購読を確定し、ステータスが確認済みになることを確認
  5. SESのConfiguration Setを開き、イベント送信先 ＞ 送信先を追加を選択
  6. 対象イベントを選択し、送信先タイプにAmazon SNS、作成したトピックを指定
  7. イベント発行を有効にして保存

SNSトピックのアクセスポリシーには、対象Configuration Setからのsns:Publishだけを許可する

json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "AllowSESPublish",
    "Effect": "Allow",
    "Principal": { "Service": "ses.amazonaws.com" },
    "Action": "sns:Publish",
    "Resource": "arn:aws:sns:<REGION>:<ACCOUNT_ID>:<SNS_TOPIC_NAME>",
    "Condition": {
      "StringEquals": {
        "AWS:SourceAccount": "<ACCOUNT_ID>",
        "AWS:SourceArn": "arn:aws:ses:<REGION>:<ACCOUNT_ID>:configuration-set/<CONFIGURATION_SET_NAME>"
      }
    }
  }]
}

作成後はSNSトピック、確認済みサブスクリプション、SESイベント送信先、選択したイベント種別を確認する

Amazon EventBridge

  1. Configuration Setのイベント送信先 ＞ 送信先を追加を選択
  2. イベントタイプの選択 ＞ 送信と配信で送信、拒否、配信、ハードバウンス、苦情数、配信の遅延をチェック
  3. テンプレート送信を監視する場合はレンダリングの失敗、リスト管理を使用する場合はサブスクリプションを追加
  4. 開封・クリック追跡を使用する場合だけ開封数とクリック数を追加し、次へを選択
  5. 送信先を指定 ＞ 送信先オプションで、送信先タイプにAmazon EventBridgeを選択
  6. 名前へses-event-bridgeを入力し、イベント発行を有効化
  7. SESイベントがEventBridgeのデフォルトイベントバスへ送信される説明を確認し、次へを選択
  8. 確認画面でイベントタイプ、送信先タイプ、名前、イベント発行の状態を確認し、送信先を追加を選択
  9. 成功メッセージとイベント送信先の概要を確認
  10. Amazon EventBridgeコンソールでイベントバス ＞ デフォルトイベントバスを開く
  11. ルールを作成でイベントパターンを使用するルールを作成
  12. イベントソースにAWSサービス、AWSサービスにSESを選択し、通知対象のイベントタイプを指定
  13. TargetへSNSトピックses-events-notificationを指定
  14. 必要に応じて再試行とSQS DLQを設定し、ルールを有効化

次のイベントパターンは、SESから発行される基本監視イベントのうち、通知が必要な失敗系のハードバウンス、苦情数、配信の遅延、拒否だけをSNSへ転送する例
送信と配信はイベント送信先からEventBridgeへ発行されるが、このルールの通知対象には含めない

json
{
  "source": ["aws.ses"],
  "detail-type": [
    "Email Bounced",
    "Email Complaint Received",
    "Email Delivery Delayed",
    "Email Rejected"
  ]
}
ℹ️ SNSとの使い分け

SNSイベント送信先は選択したSESイベントを直接通知する
EventBridgeは詳細タイプやイベント内容でルールを分け、複数サービスへ連携する場合に使用する
EventBridgeへのSESサービスイベント配信はベストエフォートのため、重要な失敗記録はSNS、SQS、ログ保存も組み合わせる

作成後はSESのEventBridge送信先、ルールのイベントパターン、Target、再試行、DLQ、ルールメトリクスを確認する

Amazon CloudWatch

  1. Configuration Setのイベント送信先 ＞ 送信先を追加を選択
  2. 対象イベントを選択し、送信先タイプにAmazon CloudWatchを指定
  3. 名前をses-cloudwatch-eventsとしてイベント発行を有効化
  4. 値のソースはメッセージタグを選択
  5. ディメンション名へses:configuration-setを指定
  6. デフォルト値へses-postfix-monitoringを指定して保存
  7. テスト送信後、CloudWatchのすべてのメトリクス ＞ SESでイベント件数を確認
⚠️ CloudWatchメトリクスの料金

イベントタイプ、ディメンション名、ディメンション値の組み合わせごとにメトリクスが作成される
受信者、Message IDなど値の種類が増え続ける項目をディメンションに使用せず、Configuration Setや用途など有限の値へ限定する

作成後はCloudWatchイベント送信先のディメンション設定と、テスト送信後に表示されたSESメトリクスを確認する

送信IDへのConfiguration Set設定

イベント送信先を作成しただけでは、送信メールへConfiguration Setは適用されない
Postfixから常に同じ設定を使用する場合は送信IDのデフォルトConfiguration Setを設定する

  1. Amazon SESコンソールで設定 ＞ IDを開く
  2. 送信に使用するドメインzexample.comを選択
  3. 設定セットタブ ＞ 編集を選択
  4. デフォルト設定セットへses-postfix-monitoringを指定
  5. 保存後、IDの設定画面へ設定セット名が表示されることを確認

送信IDに設定されたConfiguration Setを確認

CloudShell
aws sesv2 get-email-identity \
  --email-identity <SES_IDENTITY> \
  --region <REGION> \
  --query "{IdentityType:IdentityType,VerifiedForSendingStatus:VerifiedForSendingStatus,ConfigurationSetName:ConfigurationSetName}"

メール単位でデフォルト設定を上書きする場合は、SMTP送信するMIMEヘッダーへ次の値を追加する

text
X-SES-CONFIGURATION-SET: <CONFIGURATION_SET_NAME>
⚠️ デフォルト設定セットの削除

送信IDへ割り当てたデフォルトConfiguration Setを先に削除すると、そのIDを使用した送信が失敗する
削除前に送信IDとの関連付けを解除する

設定後は送信IDの設定セットタブを開き、デフォルトConfiguration Setが表示されていることを確認する

メールボックスシミュレーター

メールボックスシミュレーターは、実在しない受信者を作成せずに配信、バウンス、苦情、自動応答、サプレッションを再現する
サンドボックスでも利用でき、日次送信クォータ、バウンス率、苦情率、VDMメトリクスには影響しないが、送信料金と最大送信レートは通常どおり適用される

出典：メールボックスシミュレーター

自動応答ooto@simulator.amazonses.comDelivery後、Return-PathまたはMAIL FROMへ自動応答

テスト後はPostfixログ、SNS通知、EventBridgeイベント、CloudWatchメトリクスを、同じ送信時刻とSES Message IDで照合する

SNS／EventBridgeイベントの確認

SNS通知

  1. メール購読先へ届いたSNS通知を開く
  2. eventTypeが送信したシナリオと一致することを確認
  3. mail.messageId、mail.source、mail.destinationを確認
  4. Bounceではbounce.bounceType、bounce.bounceSubType、bouncedRecipientsを確認
  5. Complaintではcomplaint.complaintFeedbackTypeと対象受信者を確認
  6. Deliveryではdelivery.smtpResponse、processingTimeMillis、remoteMtaIpを確認

SNSへ配信されたバウンスイベントの内容を確認

json
{
  "eventType": "Bounce",
  "mail": {
    "messageId": "<SES_MESSAGE_ID>",
    "source": "<SENDER_EMAIL>",
    "destination": ["bounce@simulator.amazonses.com"]
  },
  "bounce": {
    "bounceType": "Permanent",
    "bounceSubType": "General"
  }
}

EventBridge

  1. EventBridgeルールのモニタリングでMatchedEventsとInvocationsの増加を確認
  2. TargetのSNS通知またはCloudWatch Logsでイベント本文を確認
  3. sourceがaws.sesであることを確認
  4. detail-typeがEmail Bouncedなどルールの条件と一致することを確認
  5. detail.mail.messageIdをPostfixログやSNS通知と照合
ℹ️ 個人情報の取り扱い

SNSとEventBridgeのイベントには送信元、受信者、件名、Message IDなどが含まれる場合がある
通知メール、CloudWatch Logs、S3、DLQへ保存する範囲、暗号化、保持期間、閲覧権限を事前に定義する

レピュテーションメトリクス

  1. Amazon SESコンソールのレピュテーションメトリクスを開く
  2. アカウントステータスが正常であることを確認
  3. バウンス率と苦情率の現在値、期間、傾向を確認
  4. その他の通知にスパムトラップ、認証、送信パターンなどの警告がないことを確認
  5. Configuration Set単位のレピュテーションメトリクスも確認
状態意味初動
Healthy送信機能へ影響する問題が検出されていない通常監視を継続
Under reviewレピュテーション上の問題をAWSが確認中送信を抑制し、バウンス、苦情、送信リストを調査
Pausedアカウントのメール送信が停止原因を是正し、AWSからの通知に従って再審査を依頼

CloudWatchアラームと通知

SESはアカウントレベルのReputation.BounceRateとReputation.ComplaintRateをCloudWatchへ発行する
しきい値到達前にSNSへ通知し、送信停止やリスト修正を開始できる状態にする

出典：レピュテーション監視アラーム

  1. SESのレピュテーションメトリクス ＞ バウンス率 ＞ CloudWatchで表示を選択
  2. Reputation.BounceRateのアラームアイコンを選択
  3. しきい値タイプを静的、条件を以上、値を0.05に設定
  4. 欠落データの処理は無視してアラーム状態を維持を選択
  5. アラーム状態の通知先へSNSトピックses-events-notificationを指定
  6. アラーム名をSES-Reputation-BounceRateとして作成
  7. Reputation.ComplaintRateは値を0.001として同じ流れで作成
メトリクス通知しきい値SESの推奨と注意点
Reputation.BounceRate>= 0.05（5%）5%未満を維持
10%を超えると送信停止の可能性
Reputation.ComplaintRate>= 0.001（0.1%）0.1%未満を維持
0.5%を超えると送信停止の可能性

作成後はSESレピュテーション画面、CloudWatchアラーム条件、SNS通知先、アラーム状態を確認する

サプレッションリスト

アカウントレベルのサプレッションリストは、ハードバウンスまたは苦情が発生した宛先への再送を抑止する
AWSアカウントとリージョン単位で管理され、Configuration Setから抑止理由を上書きできる

出典：アカウントレベルのサプレッションリスト

  1. Amazon SESコンソールの設定 ＞ サプレッションリストを開く
  2. アカウントレベルの設定でサプレッションリストが有効であることを確認
  3. 抑止理由としてBounceとComplaintのどちらを使用するか確認
  4. 一覧でメールアドレス、理由、登録日時を確認
  5. 対象を選択してレポートを表示を開き、原因となったイベントを確認
  6. 誤登録と判断できる場合だけ、宛先の有効性と再送許可を確認して削除

サプレッションリストを確認

CloudShell
aws sesv2 list-suppressed-destinations \
  --region <REGION> \
  --output table

対象メールアドレスの登録理由と日時を確認

CloudShell
aws sesv2 get-suppressed-destination \
  --email-address <SUPPRESSED_EMAIL_ADDRESS> \
  --region <REGION>

再送可能と判断した場合だけ対象メールアドレスを削除

CloudShell
aws sesv2 delete-suppressed-destination \
  --email-address <SUPPRESSED_EMAIL_ADDRESS> \
  --region <REGION>
⚠️ 安易に削除しない

ハードバウンスした無効な宛先を削除して再送すると、バウンス率が悪化する
アドレスの誤入力修正、受信者からの再登録、管理者による有効性確認など、再送できる根拠を記録してから削除する

確認時はアカウントレベル設定、一覧、理由、登録日時、レポート詳細を照合する

Virtual Deliverability Manager

Virtual Deliverability Manager（VDM）は、SESの配信結果をアカウント、ISP、送信ID、Configuration Set、Message ID単位で分析し、到達性に影響する設定をAdvisorで確認する有料機能

出典：Virtual Deliverability Manager

出典：Amazon SES料金

  1. Amazon SESコンソールのVirtual Deliverability Manager ＞ 概要を開く
  2. 使用開始を選択し、料金と対象リージョンを確認
  3. エンゲージメント追跡のONまたはOFFを選択
  4. 最適化された共有配信のONまたはOFFを選択
  5. 設定内容を確認してVDMを有効化
  6. Configuration SetのVDM設定でアカウント設定を継承するか上書きするか確認
  7. 管理可能な実在宛先へテストメールを送信
  8. Dashboardで配信率、バウンス、苦情、開封、クリックを確認
  9. ISP、送信ID、Configuration Set、Messagesで対象を絞り込み
  10. Advisorで未解決の推奨事項と修正方法を確認
⚠️ エンゲージメント追跡

有効にすると、開封確認用の要素が追加され、リンクURLがSESの追跡用URLへ書き換えられる
プライバシーポリシー、セキュリティ製品によるURL検査、トランザクションメールの要件を確認してから有効化する

⚠️ 最適化された共有配信

送信レピュテーションを保護するため、メール送信が事前に遅延する可能性がある
即時性が必要な通知ではアカウント全体へ一律適用せず、Configuration Set単位で無効化を検討する

ℹ️ シミュレーターはVDMへ反映されない

メールボックスシミュレーターへの送信はVDMメトリクスへ影響しない
Dashboardの検証には、自分で管理できる実在のテスト受信先を使用する

VDMを検証するときは、設定、Dashboard、ISP、送信ID、Configuration Set、Messages、Advisorを確認する

送信クォータとサンドボックス

送信クォータとサンドボックス状態はAWSアカウントとリージョンごとに独立する

出典：Amazon SES Service Quotas

  1. Amazon SESコンソールのアカウントダッシュボードを開く
  2. 本番アクセスが有効か、サンドボックスかを確認
  3. 24時間あたりの送信クォータ、過去24時間の送信数、残数を確認
  4. 1秒あたりの最大送信レートを確認
  5. 送信量が上限へ近づく前に、用途と送信パターンを整理して引き上げを申請

送信クォータとサンドボックス状態を確認

CloudShell
aws sesv2 get-account \
  --region <REGION> \
  --query "{ProductionAccessEnabled:ProductionAccessEnabled,EnforcementStatus:EnforcementStatus,SendQuota:SendQuota,SendingEnabled:SendingEnabled}"
項目サンドボックス本番アクセス
通常宛先検証済み受信者だけ通常の受信者へ送信可能
24時間の送信数最大200受信者アカウントとリージョンごとの割当
最大送信レート1受信者／秒アカウントとリージョンごとの割当
シミュレーター利用可能利用可能
ℹ️ クォータは受信者数で計算

To、CC、BCCを含む受信者数がクォータへ加算される
1通を10人へ送信すると10として扱われ、クォータとサンドボックス状態はリージョンごとに異なる

障害時の切り分け

症状主な確認項目対応
Postfixはstatus=sentだがイベントがない送信IDのデフォルトConfiguration Set、X-SES-CONFIGURATION-SET、リージョン実際に使用した送信IDへConfiguration Setを割り当て、再送
SNS通知が届かない購読状態、イベント種別、送信先の有効状態、トピックポリシー購読を確認済みにし、SESのsns:Publishを許可
EventBridgeルールに一致しないsource、detail-type、リージョン、デフォルトイベントバスSandboxのサンプルイベントでパターンを検証し、ルールメトリクスを確認
CloudWatchメトリクスがないイベント送信先、ディメンション名と値、送信実績、リージョン有限のデフォルト値を設定し、同じリージョンでテスト送信
バウンスまたは苦情が増加SNSイベント、サプレッションリスト、送信元リスト、取得経路対象リストへの送信を停止し、無効宛先と同意状況を是正
アラームがINSUFFICIENT_DATASES送信実績、メトリクスのリージョン、欠落データ設定テスト送信後にデータを確認し、欠落データを無視に設定
VDMにシミュレーターの結果がない送信先がsimulator.amazonses.comか管理可能な実在受信先で検証
VDMの開封・クリックがないエンゲージメント追跡、画像読み込み、リンク、Configuration Set上書き追跡設定と受信クライアントのプライバシー機能を確認
サプレッションされた宛先へ再送したい登録理由、アドレスの有効性、受信者の再同意再送根拠を確認した場合だけリストから削除
送信がスロットリングされる最大送信レート、過去24時間の送信数、Postfixキュー送信速度を制御し、必要に応じてクォータ引き上げを申請
