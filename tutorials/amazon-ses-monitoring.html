Amazon SES 配信監視

Amazon SESから送信したメールの配信、バウンス、苦情、遅延を収集し、異常を通知する運用手順を整理する。Configuration Setを起点にSNS、EventBridge、CloudWatchを設定し、サプレッションリスト、VDM、送信クォータまで確認する

配信監視の全体像

SMTPサーバーでstatus=sentになっても、SESが受信者のメールサーバーへ配信したことまでは保証しない。PostfixからSESへの引き渡し、SESの配信イベント、受信者側の結果を分けて確認する

確認レイヤー確認内容主な確認先
PostfixSES SMTPエンドポイントへ引き渡せたかjournalctl、メールキュー
Amazon SESSend、Delivery、Bounce、Complaint、DeliveryDelayConfiguration Setのイベント送信先
通知即時通知、イベント振り分け、メトリクスアラームSNS、EventBridge、CloudWatch
レピュテーションバウンス率、苦情率、アカウント状態SESレピュテーションメトリクス
到達性ISP、送信ID、Configuration Set別の配信傾向Virtual Deliverability Manager
📌 このページの検証構成

東京リージョン、Configuration Set名ses-postfix-monitoring、SNSトピック名ses-events-notificationを例にする。名前、ARN、送信ID、メールアドレスは環境に合わせて変更する

Configuration Setの作成

Configuration Setは、イベント送信先、レピュテーションメトリクス、VDM設定などを送信メールへまとめて適用する単位。同じ送信IDでも、トランザクションメールとマーケティングメールを分けると、監視と変更管理を独立させやすい。設定項目はAWS公式のConfiguration Set作成手順を参照する

  1. Amazon SESコンソールを東京リージョンで開き、「設定」「設定セット」を選択
  2. 「セットの作成」を選択
  3. 設定セット名へses-postfix-monitoringを入力
  4. 送信オプションが有効であることを確認
  5. レピュテーションメトリクスを有効化
  6. サプレッションリストとVDMはアカウント設定を継承し、必要な場合だけConfiguration Set単位で上書き
  7. タグを設定し、「セットの作成」を選択
powershell
aws sesv2 get-configuration-set `
  --configuration-set-name ses-postfix-monitoring `
  --region ap-northeast-1

イベント送信先の作成

Configuration Setの「イベント送信先」で、収集するイベントと出力先を設定する。1つのConfiguration Setには複数のイベント送信先を作成できるため、通知用SNS、振り分け用EventBridge、集計用CloudWatchを分けて設定する。選択できるイベントと送信先はAWS公式のイベント送信先の作成を参照する

送信先向いている用途保持・確認方法
Amazon SNSバウンスや苦情をメール、SMS、Lambdaなどへ即時通知購読先へJSONイベントを配信
Amazon EventBridgeイベント種別で振り分け、SNS、SQS、Lambda、Step Functionsへ連携ルールのメトリクス、Target、DLQで確認
Amazon CloudWatchイベント件数をメトリクス化し、ダッシュボードとアラームで監視AWS/SESメトリクスで確認

最初の検証ではSend、Delivery、Bounce、Complaint、DeliveryDelay、Rejectを対象とする。OpenとClickはエンゲージメント追跡を利用する場合だけ追加する

Amazon SNS

  1. Amazon SNSコンソールで「トピック」「トピックの作成」を選択
  2. タイプは「スタンダード」、名前はses-events-notificationとして作成
  3. 「サブスクリプションの作成」で通知先メールアドレスを登録
  4. 届いた確認メールから購読を確定し、ステータスが「確認済み」になることを確認
  5. SESのConfiguration Setを開き、「イベント送信先」「送信先を追加」を選択
  6. 対象イベントを選択し、送信先タイプにAmazon SNS、作成したトピックを指定
  7. イベント発行を有効にして保存

SNSトピックのアクセスポリシーには、対象Configuration Setからのsns:Publishだけを許可する

json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "AllowSESPublish",
    "Effect": "Allow",
    "Principal": { "Service": "ses.amazonaws.com" },
    "Action": "sns:Publish",
    "Resource": "arn:aws:sns:ap-northeast-1:<ACCOUNT_ID>:ses-events-notification",
    "Condition": {
      "StringEquals": {
        "AWS:SourceAccount": "<ACCOUNT_ID>",
        "AWS:SourceArn": "arn:aws:ses:ap-northeast-1:<ACCOUNT_ID>:configuration-set/ses-postfix-monitoring"
      }
    }
  }]
}

Amazon EventBridge

  1. Configuration Setの「イベント送信先」「送信先を追加」を選択
  2. 対象イベントを選択し、送信先タイプにAmazon EventBridgeを指定
  3. 名前をses-event-bridgeとしてイベント発行を有効化
  4. Amazon EventBridgeコンソールでデフォルトイベントバスを開く
  5. 「ルールを作成」でイベントパターンを使用するルールを作成
  6. イベントソースをaws.ses、通知対象の詳細タイプを指定
  7. TargetへSNSトピックses-events-notificationを指定
  8. 必要に応じて再試行とSQS DLQを設定し、ルールを有効化
json
{
  "source": ["aws.ses"],
  "detail-type": [
    "Email Bounced",
    "Email Complaint Received",
    "Email Delivery Delayed",
    "Email Rejected"
  ]
}
ℹ️ SNSとの使い分け

SNSイベント送信先は選択したSESイベントを直接通知する。EventBridgeは詳細タイプやイベント内容でルールを分け、複数サービスへ連携する場合に使用する。EventBridgeへのSESサービスイベント配信はベストエフォートのため、重要な失敗記録はSNS、SQS、ログ保存も組み合わせる

Amazon CloudWatch

  1. Configuration Setの「イベント送信先」「送信先を追加」を選択
  2. 対象イベントを選択し、送信先タイプにAmazon CloudWatchを指定
  3. 名前をses-cloudwatch-eventsとしてイベント発行を有効化
  4. 値のソースは「メッセージタグ」を選択
  5. ディメンション名へses:configuration-setを指定
  6. デフォルト値へses-postfix-monitoringを指定して保存
  7. テスト送信後、CloudWatchの「すべてのメトリクス」「SES」でイベント件数を確認
⚠️ CloudWatchメトリクスの料金

イベントタイプ、ディメンション名、ディメンション値の組み合わせごとにメトリクスが作成される。受信者、Message IDなど値の種類が増え続ける項目をディメンションに使用せず、Configuration Setや用途など有限の値へ限定する

送信IDへのConfiguration Set設定

イベント送信先を作成しただけでは、送信メールへConfiguration Setは適用されない。Postfixから常に同じ設定を使用する場合は送信IDのデフォルトConfiguration Setを設定する

  1. Amazon SESコンソールで「設定」「ID」を開く
  2. 送信に使用するドメインzexample.comを選択
  3. 「設定セット」タブの「編集」を選択
  4. デフォルト設定セットへses-postfix-monitoringを指定
  5. 保存後、IDの設定画面へ設定セット名が表示されることを確認
powershell
aws sesv2 get-email-identity `
  --email-identity zexample.com `
  --region ap-northeast-1 `
  --query "{IdentityType:IdentityType,VerifiedForSendingStatus:VerifiedForSendingStatus,ConfigurationSetName:ConfigurationSetName}"

メール単位でデフォルト設定を上書きする場合は、SMTP送信するMIMEヘッダーへ次の値を追加する

text
X-SES-CONFIGURATION-SET: ses-postfix-monitoring
⚠️ デフォルト設定セットの削除

送信IDへ割り当てたデフォルトConfiguration Setを先に削除すると、そのIDを使用した送信が失敗する。削除前に送信IDとの関連付けを解除する

メールボックスシミュレーター

メールボックスシミュレーターは、実在しない受信者を作成せずに配信、バウンス、苦情、自動応答、サプレッションを再現する。サンドボックスでも利用でき、日次送信クォータ、バウンス率、苦情率、VDMメトリクスには影響しないが、送信料金と最大送信レートは通常どおり適用される。動作条件はAWS公式のメールボックスシミュレーターを参照する

シナリオ宛先期待する結果
正常配信success@simulator.amazonses.comSend、Delivery
ハードバウンスbounce@simulator.amazonses.comSend、Bounce。シミュレーター自体はサプレッションリストへ追加されない
苦情complaint@simulator.amazonses.comSend、Delivery、Complaint
自動応答ooto@simulator.amazonses.comDelivery後、Return-PathまたはMAIL FROMへ自動応答
サプレッションsuppressionlist@simulator.amazonses.comグローバルサプレッションリストに存在する場合と同様のBounce

正常配信

root shell
echo "SES delivery monitoring test" | mailx -v -r no-reply@zexample.com -s "SES success test" success@simulator.amazonses.com

バウンス

root shell
echo "SES bounce monitoring test" | mailx -v -r no-reply@zexample.com -s "SES bounce test" bounce@simulator.amazonses.com

苦情

root shell
echo "SES complaint monitoring test" | mailx -v -r no-reply@zexample.com -s "SES complaint test" complaint@simulator.amazonses.com

自動応答

root shell
echo "SES out-of-office monitoring test" | mailx -v -r no-reply@zexample.com -s "SES OOTO test" ooto@simulator.amazonses.com

サプレッション

root shell
echo "SES suppression monitoring test" | mailx -v -r no-reply@zexample.com -s "SES suppression test" suppressionlist@simulator.amazonses.com

各コマンドのPostfixログ、SNS通知、EventBridgeイベント、CloudWatchメトリクスを同じ送信時刻とSES Message IDで対応付ける

SNS／EventBridgeイベントの確認

SNS通知

  1. メール購読先へ届いたSNS通知を開く
  2. eventTypeが送信したシナリオと一致することを確認
  3. mail.messageId、mail.source、mail.destinationを確認
  4. Bounceではbounce.bounceType、bounce.bounceSubType、bouncedRecipientsを確認
  5. Complaintではcomplaint.complaintFeedbackTypeと対象受信者を確認
  6. Deliveryではdelivery.smtpResponse、processingTimeMillis、remoteMtaIpを確認
json
{
  "eventType": "Bounce",
  "mail": {
    "messageId": "<SES_MESSAGE_ID>",
    "source": "no-reply@zexample.com",
    "destination": ["bounce@simulator.amazonses.com"]
  },
  "bounce": {
    "bounceType": "Permanent",
    "bounceSubType": "General"
  }
}

EventBridge

  1. EventBridgeルールの「モニタリング」でMatchedEventsとInvocationsの増加を確認
  2. TargetのSNS通知またはCloudWatch Logsでイベント本文を確認
  3. sourceがaws.sesであることを確認
  4. detail-typeがEmail Bouncedなどルールの条件と一致することを確認
  5. detail.mail.messageIdをPostfixログやSNS通知と照合
ℹ️ 個人情報の取り扱い

SNSとEventBridgeのイベントには送信元、受信者、件名、Message IDなどが含まれる場合がある。通知メール、CloudWatch Logs、S3、DLQへ保存する範囲、暗号化、保持期間、閲覧権限を事前に定義する

レピュテーションメトリクス

  1. Amazon SESコンソールの「レピュテーションメトリクス」を開く
  2. アカウントステータスが「正常」であることを確認
  3. バウンス率と苦情率の現在値、期間、傾向を確認
  4. その他の通知にスパムトラップ、認証、送信パターンなどの警告がないことを確認
  5. Configuration Set単位のレピュテーションメトリクスも確認
状態意味初動
Healthy送信機能へ影響する問題が検出されていない通常監視を継続
Under reviewレピュテーション上の問題をAWSが確認中送信を抑制し、バウンス、苦情、送信リストを調査
Pausedアカウントのメール送信が停止原因を是正し、AWSからの通知に従って再審査を依頼

CloudWatchアラームと通知

SESはアカウントレベルのReputation.BounceRateとReputation.ComplaintRateをCloudWatchへ発行する。しきい値到達前にSNSへ通知し、送信停止やリスト修正を開始できる状態にする。推奨しきい値と設定手順はAWS公式のレピュテーション監視アラームを参照する

  1. SESの「レピュテーションメトリクス」でバウンス率の「CloudWatchで表示」を選択
  2. Reputation.BounceRateのアラームアイコンを選択
  3. しきい値タイプを「静的」、条件を「以上」、値を0.05に設定
  4. 欠落データの処理は「無視してアラーム状態を維持」を選択
  5. アラーム状態の通知先へSNSトピックses-events-notificationを指定
  6. アラーム名をSES-Reputation-BounceRateとして作成
  7. Reputation.ComplaintRateは値を0.001として同じ流れで作成
メトリクス通知しきい値SESの推奨と注意点
Reputation.BounceRate>= 0.05（5%）5%未満を維持。10%を超えると送信停止の可能性
Reputation.ComplaintRate>= 0.001（0.1%）0.1%未満を維持。0.5%を超えると送信停止の可能性

サプレッションリスト

アカウントレベルのサプレッションリストは、ハードバウンスまたは苦情が発生した宛先への再送を抑止する。AWSアカウントとリージョン単位で管理され、Configuration Setから抑止理由を上書きできる。動作と制約はAWS公式のアカウントレベルのサプレッションリストを参照する

  1. Amazon SESコンソールの「設定」「サプレッションリスト」を開く
  2. 「アカウントレベルの設定」でサプレッションリストが有効であることを確認
  3. 抑止理由としてBounceとComplaintのどちらを使用するか確認
  4. 一覧でメールアドレス、理由、登録日時を確認
  5. 対象を選択して「レポートを表示」を開き、原因となったイベントを確認
  6. 誤登録と判断できる場合だけ、宛先の有効性と再送許可を確認して削除
powershell
aws sesv2 list-suppressed-destinations `
  --region ap-northeast-1 `
  --output table
powershell
aws sesv2 get-suppressed-destination `
  --email-address <SUPPRESSED_EMAIL_ADDRESS> `
  --region ap-northeast-1
powershell
aws sesv2 delete-suppressed-destination `
  --email-address <SUPPRESSED_EMAIL_ADDRESS> `
  --region ap-northeast-1
⚠️ 安易に削除しない

ハードバウンスした無効な宛先を削除して再送すると、バウンス率が悪化する。アドレスの誤入力修正、受信者からの再登録、管理者による有効性確認など、再送できる根拠を記録してから削除する

アカウントレベル設定、一覧、理由、登録日時、レポート詳細を画像で記録する。メールアドレスとMessage IDは公開前にマスクする

Virtual Deliverability Manager

Virtual Deliverability Manager（VDM）は、SESの配信結果をアカウント、ISP、送信ID、Configuration Set、Message ID単位で分析し、到達性に影響する設定をAdvisorで確認する有料機能。機能はAWS公式のVirtual Deliverability Manager、利用前の料金はAmazon SES料金を確認する

  1. Amazon SESコンソールの「Virtual Deliverability Manager」「概要」を開く
  2. 使用開始を選択し、料金と対象リージョンを確認
  3. エンゲージメント追跡のONまたはOFFを選択
  4. 最適化された共有配信のONまたはOFFを選択
  5. 設定内容を確認してVDMを有効化
  6. Configuration SetのVDM設定でアカウント設定を継承するか上書きするか確認
  7. 管理可能な実在宛先へテストメールを送信
  8. Dashboardで配信率、バウンス、苦情、開封、クリックを確認
  9. ISP、送信ID、Configuration Set、Messagesで対象を絞り込み
  10. Advisorで未解決の推奨事項と修正方法を確認
⚠️ エンゲージメント追跡

有効にすると、開封確認用の要素が追加され、リンクURLがSESの追跡用URLへ書き換えられる。プライバシーポリシー、セキュリティ製品によるURL検査、トランザクションメールの要件を確認してから有効化する

⚠️ 最適化された共有配信

送信レピュテーションを保護するため、メール送信が事前に遅延する可能性がある。即時性が必要な通知ではアカウント全体へ一律適用せず、Configuration Set単位で無効化を検討する

ℹ️ シミュレーターはVDMへ反映されない

メールボックスシミュレーターへの送信はVDMメトリクスへ影響しない。Dashboardの検証には、自分で管理できる実在のテスト受信先を使用する

🧪 実機検証で記録する内容

VDMの設定、Dashboard全体、ISP、送信ID、Configuration Set、Messages、Advisorを画像で記録する。受信者、件名、Message ID、アカウント情報は公開前にマスクする

送信クォータとサンドボックス

送信クォータとサンドボックス状態はAWSアカウントとリージョンごとに独立する。上限値と調整可否はAWS公式のAmazon SES Service Quotasを参照する

  1. Amazon SESコンソールの「アカウントダッシュボード」を開く
  2. 本番アクセスが有効か、サンドボックスかを確認
  3. 24時間あたりの送信クォータ、過去24時間の送信数、残数を確認
  4. 1秒あたりの最大送信レートを確認
  5. 送信量が上限へ近づく前に、用途と送信パターンを整理して引き上げを申請
powershell
aws sesv2 get-account `
  --region ap-northeast-1 `
  --query "{ProductionAccessEnabled:ProductionAccessEnabled,EnforcementStatus:EnforcementStatus,SendQuota:SendQuota,SendingEnabled:SendingEnabled}"
項目サンドボックス本番アクセス
通常宛先検証済み受信者だけ通常の受信者へ送信可能
24時間の送信数最大200受信者アカウントとリージョンごとの割当
最大送信レート1受信者／秒アカウントとリージョンごとの割当
シミュレーター利用可能利用可能
ℹ️ クォータは受信者数で計算

To、CC、BCCを含む受信者数がクォータへ加算される。1通を10人へ送信すると10として扱われ、クォータとサンドボックス状態はリージョンごとに異なる

障害時の切り分け

症状主な確認項目対応
Postfixはstatus=sentだがイベントがない送信IDのデフォルトConfiguration Set、X-SES-CONFIGURATION-SET、リージョン実際に使用した送信IDへConfiguration Setを割り当て、再送
SNS通知が届かない購読状態、イベント種別、送信先の有効状態、トピックポリシー購読を確認済みにし、SESのsns:Publishを許可
EventBridgeルールに一致しないsource、detail-type、リージョン、デフォルトイベントバスSandboxのサンプルイベントでパターンを検証し、ルールメトリクスを確認
CloudWatchメトリクスがないイベント送信先、ディメンション名と値、送信実績、リージョン有限のデフォルト値を設定し、同じリージョンでテスト送信
バウンスまたは苦情が増加SNSイベント、サプレッションリスト、送信元リスト、取得経路対象リストへの送信を停止し、無効宛先と同意状況を是正
アラームがINSUFFICIENT_DATASES送信実績、メトリクスのリージョン、欠落データ設定テスト送信後にデータを確認し、欠落データを「無視」に設定
VDMにシミュレーターの結果がない送信先がsimulator.amazonses.comか管理可能な実在受信先で検証
VDMの開封・クリックがないエンゲージメント追跡、画像読み込み、リンク、Configuration Set上書き追跡設定と受信クライアントのプライバシー機能を確認
サプレッションされた宛先へ再送したい登録理由、アドレスの有効性、受信者の再同意再送根拠を確認した場合だけリストから削除
送信がスロットリングされる最大送信レート、過去24時間の送信数、Postfixキュー送信速度を制御し、必要に応じてクォータ引き上げを申請
