Git / GitHub 基本編

GitとGitHubの導入、認証、ブランチ操作、Pull Request、レビュー、IaC開発で必要な基本操作を整理する

0. GitとGitHub

名称役割
Gitファイルの変更履歴をローカルで記録し、差分、ブランチ、コミットを管理するバージョン管理システム
GitHubGitリポジトリを共有し、Pull Request、レビュー、Issue、Actionsなどで共同作業するサービス
ローカルリポジトリ作業端末にある履歴管理済みのディレクトリ
リモートリポジトリGitHubなどに置かれた共有先のリポジトリ

実務では次の順番を一つの流れとして扱う

  1. 最新のmainを取得
  2. 作業用ブランチを作成
  3. VS Codeで変更
  4. 差分を確認してステージング
  5. コミットしてGitHubへpush
  6. Pull Requestを作成
  7. レビュー指摘を同じブランチで修正
  8. マージ後にローカルのmainを同期

1. GitとVS Codeのインストール

PowerShellを開き、Gitをインストール

powershell
winget install --id Git.Git -e --source winget

Visual Studio CodeとGitHub CLIをインストール

powershell
winget install --id Microsoft.VisualStudioCode -e --source winget
powershell
winget install --id GitHub.cli -e --source winget

PowerShellを開き直し、バージョンを確認

powershell
git --version
code --version
gh --version

2. Gitの初期設定

コミットに記録するユーザー名とメールアドレスを設定

powershell
git config --global user.name "thsmt"
git config --global user.email "<GITHUB_EMAIL>"
git config --global init.defaultBranch main

設定値と設定元ファイルを確認

powershell
git config --global --list --show-origin
ℹ️ メールアドレス

GitHubのプロフィールへコミットを反映する場合は、GitHubへ登録済みのメールアドレスまたはGitHubが提供するnoreplyアドレスを使用する

⚠️ 改行コード

core.autocrlfを既存リポジトリの方針を確認せず変更すると、大量の改行差分が発生する

チームで管理する.gitattributesを優先し、設定変更前にリポジトリの規約を確認する

3. GitHub認証（HTTPS）

この基本編では、GitHub CLIのブラウザ認証とHTTPSを使用

3.1 ブラウザで認証

ブラウザ認証を開始

powershell
gh auth login

GitHub.com、HTTPSを選択

Authenticate Git with your GitHub credentials?はYesを選択し、Login with a web browserから認証

ℹ️ 情報

Yesを選択すると、GitHub CLIの認証情報をHTTPSによるclone、pull、pushにも利用できる

ワンタイムコードは認証画面だけで使用し、手順書、Git、スクリーンショットへ記録しない

3.2 認証状態の確認

PowerShellで認証先アカウント、Gitプロトコル、認証状態を確認

powershell
gh auth status

GitHubの画面では、プロフィール画像、Settings、Applications、Authorized OAuth AppsからGitHub CLIの認可を確認

3.3 再認証

認証期限切れ、認証エラー、利用アカウント変更時は、ローカルの認証情報を削除して再認証

powershell
gh auth logout -h github.com -u <GITHUB_USER>
gh auth login -h github.com --git-protocol https --web
ℹ️ 情報

gh auth logoutは端末内の認証情報を削除する操作であり、GitHub側のOAuth認可は取り消さない

GitHub側の認可も取り消す場合は、Authorized OAuth AppsのGitHub CLIからRevokeを実行

4. リポジトリのclone

ローカルリポジトリを置くディレクトリを作成

powershell
New-Item -ItemType Directory -Path "$env:USERPROFILE\Documents\Git" -Force
Set-Location "$env:USERPROFILE\Documents\Git"

HTTPSのURLでclone

powershell
git clone https://github.com/<OWNER>/<REPOSITORY>.git
Set-Location <REPOSITORY>

ブランチ、リモート、作業ツリーを確認

powershell
git branch --show-current
git remote -v
git status

5. ブランチでの変更作業

5.1 mainを最新化

powershell
git switch main
git pull --ff-only origin main

--ff-onlyは意図しないマージコミットを作らず、fast-forwardできない場合に処理を停止する

5.2 作業ブランチを作成

powershell
git switch -c docs/git-basics

ブランチ名はfeature/、fix/、docs/などの種別と作業内容を組み合わせる

5.3 VS Codeで編集

powershell
code .

5.4 変更内容を確認

powershell
git status
git diff

5.5 必要なファイルだけをステージング

powershell
git add README.md
git add docs/learning-log.md
git diff --staged

git addはコミット対象を選ぶ操作であり、GitHubへ送信する操作ではない

5.6 コミット

powershell
git commit -m "Add Git workflow learning log"

コミットメッセージは変更内容が一目で分かる命令形または簡潔な現在形で記載する

5.7 GitHubへpush

powershell
git push -u origin docs/git-basics

2回目以降は追跡先が設定されているためgit pushで更新できる

6. Pull Request

  1. GitHubで対象リポジトリを開く
  2. Compare & pull requestを選択
  3. baseがmain、compareが作業ブランチであることを確認
  4. 目的、変更内容、確認結果、影響範囲を記載
  5. 必要なReviewerを指定してPull Requestを作成
記載項目内容
目的なぜ変更するのか
変更内容どのファイルと動作を変更したのか
確認結果実行したテスト、validate、plan、diffの結果
影響範囲停止、置換、削除、料金、後方互換性への影響
切り戻し問題発生時に元へ戻す方法

GitHub CLIを利用する場合

powershell
gh pr create --fill

レビュー方法と各判定の使い分けはGitHub公式のPull Requestで提案された変更をレビューするも参照する

7. レビュー対応

ReviewerはFiles changedで差分を確認し、コメント、Approve、Request changesを選択する

修正依頼を受けた場合は同じ作業ブランチで修正し、再度コミットとpushを実行

powershell
git status
git diff
git add <CHANGED_FILE>
git diff --staged
git commit -m "Address review feedback"
git push

同じブランチへpushすると、既存のPull Requestへコミットが自動追加される

GitHub CLIでPull Requestとチェックを確認

powershell
gh pr view --web
gh pr diff
gh pr checks

8. マージ後の同期

Pull Requestがマージされた後、ローカルのmainを最新化

powershell
git switch main
git pull --ff-only origin main
git branch -d docs/git-basics
git fetch --prune

git branch -dはマージ済みブランチだけを削除し、未マージの場合は停止する

9. VS Codeでの操作

操作VS CodeCLI
変更確認Source Controlでファイルを選択git diff
ステージング対象ファイルの+を選択git add <FILE>
コミットメッセージを入力してCommitgit commit -m
ブランチ切り替え左下のブランチ名を選択git switch
同期Sync ChangesまたはPushgit push

VS CodeとCLIは同じ.gitディレクトリを操作するため、片方で行った変更はもう片方にも反映される

画面操作はVisual Studio Code公式のSource Control in VS Codeで確認できる

10. IaC開発での確認

対象コミット前の主な確認Gitへ含めないもの
Terraformterraform fmt -check、terraform validate、terraform plan.terraform/、*.tfstate、認証情報を含む変数ファイル
AWS CDKテスト、cdk synth、cdk diffcdk.out/、一時生成物、認証情報
CloudFormationvalidate-template、変更セット、作成・置換・削除対象機密パラメータ、実環境の秘密値
⚠️ シークレット

アクセスキー、秘密鍵、パスワード、トークン、顧客情報を一度でもpushした場合は、履歴から削除するだけでなく認証情報を失効・再発行する

11. 避ける操作

操作問題代替
mainへ直接コミットレビューと自動テストを経由できない作業ブランチとPull Requestを使用
確認せずgit add .秘密情報や無関係な変更を含めやすいgit status後にファイル単位で追加
共有ブランチへのpush --force他メンバーの履歴を上書きするチームルールを確認し、必要時は--force-with-leaseを限定利用
理由を確認しないreset --hard未コミットの変更を失うstatus、diff、stash、restoreを用途別に選択
複数目的を一つのコミットへ混在レビューと切り戻しが難しい一つの目的ごとに小さくコミット
説明のないPull Request影響範囲と確認結果を判断できない目的、変更、検証、影響、切り戻しを記載

12. 初回演習

練習用のPrivateリポジトリを作成し、次のファイル構成を用意する

text
git-github-practice/
├─ README.md
├─ .gitignore
└─ docs/
   └─ learning-log.md
  1. リポジトリをclone
  2. docs/first-pull-requestブランチを作成
  3. docs/learning-log.mdへ学習内容を追記
  4. statusとdiffを確認
  5. 対象ファイルだけをステージング
  6. コミットしてpush
  7. Pull Requestを作成
  8. 自身でFiles changedを確認し、コメントを一つ追加
  9. 追加修正をpushしてPull Requestを更新
  10. マージ後にローカルのmainを同期

最後にブランチと直近のコミット履歴を確認

powershell
git branch --show-current
git log --oneline --decorate -5
git status
