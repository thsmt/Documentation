Windows Server 2025

⚡ このページの要約

Amazon EC2上でWindows Server 2025 Baseを初期構築し、接続、ローカルユーザー、OS、AWS管理機能の設定手順をまとめる
再起動を伴うコンピューター名変更とWindows Updateを最後に実施し、設定後の確認方法を整理する

AMIの違い

AMIについては、BaseがデスクトップGUI付き、CoreがGUIを含まないServer Core。今回のcompmgmt.mscによる手順ではBaseを選択する。CoreはPowerShell、SConfig、Windows Admin Centerなどによる管理向け

AMI画面と管理方法
Base
Windows_Server-2025-English-Full-Base		デスクトップエクスペリエンスを含み、通常のWindows GUI、サーバーマネージャー、MMC、リモートデスクトップを利用できる
Core
Windows_Server-2025-English-Core-Base		標準のデスクトップGUIを含まないServer Core。PowerShell、SConfig、Windows Admin Center、RSATなどで管理する

出典：Microsoft公式: Server Coreとデスクトップエクスペリエンスの違い

$result = $searcher.Search("IsInstalled=0 and IsHidden=0 and Type='Software'")
$updates = New-Object -ComObject Microsoft.Update.UpdateColl
foreach ($update in $result.Updates) {
  if (-not $update.EulaAccepted) { $update.AcceptEula() }
  [void]$updates.Add($update)
}
if ($updates.Count -gt 0) {
  $downloader = $session.CreateUpdateDownloader()
  $downloader.Updates = $updates
  [void]$downloader.Download()
  $installer = $session.CreateUpdateInstaller()
  $installer.Updates = $updates
  $installResult = $installer.Install()
  $installResult | Select-Object ResultCode, RebootRequired
}

0. 起動時の確認

0.1 AMIとキーペア

AWSが提供するWindows Server 2025 AMIを選択し、秘密鍵を安全に管理できるRSAキーペアを指定する

⚠️ 注意

Amazon EC2のWindowsインスタンスはED25519キーペアに対応していません。Administratorの初期パスワードを復号できるよう、Windows ServerではRSAキーペアを使用する

0.2 構築値

値用途
<WINDOWS_PRIVATE_IP>RDP接続先のプライベートIPアドレス
<KEY_PAIR_NAME>Administrator初期パスワードの復号に使用するRSAキーペア
<HOSTNAME>Windows Serverへ設定するコンピューター名
<ADMIN_USER>管理用ローカルユーザー名
<CUSTOMER_USER>利用者用ローカルユーザー名
<DESCRIPTION>ローカルユーザーの用途を示す説明
<DISK_NUMBER>初期化する追加ディスクの番号
<VOLUME_DRIVE_LETTER>追加ボリュームへ割り当てるドライブ文字。例: D:
<VOLUME_LABEL>追加ボリュームへ設定するラベル

0.3 Windows Server 2025の既定値差分

機能Windows Server 2025での確認点
TLS 1.0 / 1.1Windows Server 2025では既定で無効。新規AMIではレジストリを追加変更せず、アップグレード環境や明示的な上書きがある場合だけ確認
Credential Guard要件を満たすドメイン参加済みの非ドメインコントローラーでは既定で有効。ワークグループ環境や要件を満たさない環境では状態を個別確認
OpenSSH Serverコンポーネントが既定でインストール済み。使用する場合だけサービス起動と通信許可を設定
SMB署名送信SMB接続で署名が既定必須。旧NASや古いSMB実装との互換性を確認
SMB認証レート制限SMBサーバーで既定有効。不正な認証試行の間隔を設け、総当たり攻撃を抑制
SMBファイアウォール新しい共有ルールではNetBIOSポート137から139を既定で含めない
RRAS新規構成ではPPTPとL2TPを既定で受け付けない。IKEv2またはSSTPを優先
WinGetコマンドラインパッケージ管理ツールが標準搭載

出典：Microsoft公式: Windows Server 2025の新機能

出典：Microsoft公式: Windows Serverで削除または非推奨となった機能

1. Windowsインスタンス接続

1.1 Administratorパスワード取得

  1. Amazon EC2コンソールで対象インスタンスを選択
  2. アクション ＞ セキュリティ ＞ Windowsパスワードを取得を選択
  3. 起動時に指定したRSAキーペアの秘密鍵をアップロード
  4. パスワードを復号化を選択
  5. 表示されたAdministratorパスワードを認証情報管理ルールに従って保管

1.2 踏み台経由のRDP接続

  1. 踏み台サーバーへSSH接続
  2. SSHクライアントでローカルポートフォワードを設定
  3. ローカルポートへ未使用の任意ポートを指定。例: 65001
  4. 転送先へ<WINDOWS_PRIVATE_IP>:3389を指定
  5. リモートデスクトップクライアントで127.0.0.1:65001へ接続
  6. Administratorと復号したパスワードでサインイン

1.3 Fleet Manager Remote Desktop接続

  1. AWS Systems ManagerのFleet Managerで対象のマネージドノードを選択
  2. ノードアクション ＞ リモートデスクトップで接続を選択
  3. ユーザー認証情報を使用する接続方式を選択
  4. Administratorと復号したパスワードで接続
ℹ️ 情報

Fleet Managerを利用するEC2インスタンスには、SSM AgentとAmazonSSMManagedInstanceCore相当の権限を持つIAMインスタンスプロファイルが必要です。インスタンスへアクセスキーを保存せず、IAMロールで権限を付与する

2. ローカルユーザー作成

2.1 管理用ローカルユーザー

  1. Windows + Rを押し、compmgmt.mscを実行
  2. ローカル ユーザーとグループ ＞ ユーザーを開く
  3. メニューバーの操作(A) ＞ 新しいユーザー(N)を選択
  4. ユーザー名へ<ADMIN_USER>を入力
  5. パスワード運用要件に合わせて初回変更と有効期限を設定
  6. 作成(E)を選択
  7. ユーザー一覧で作成したユーザーをダブルクリック
  8. 所属するグループタブを選択し、追加(D)を選択
  9. 選択するオブジェクト名を入力してくださいへAdministratorsを入力
  10. 名前の確認(C)を選択し、名前が解決されたことを確認してOKを選択
  11. 所属するグループにAdministratorsが追加されたことを確認

2.2 利用者用ローカルユーザー

管理者権限でPowerShellを起動し、パスワードを対話入力で受け取り、パスワードとアカウントの有効期限を無期限にしたローカルユーザーを作成してAdministratorsグループへ追加する

powershell
$Password = Read-Host -AsSecureString "パスワードを入力"
powershell
New-LocalUser -Name "<CUSTOMER_USER>" -Password $Password -PasswordNeverExpires -AccountNeverExpires -Description "<DESCRIPTION>"
powershell
Add-LocalGroupMember -Group "Administrators" -Member "<CUSTOMER_USER>"

出典：Microsoft公式: New-LocalUser

3. Windows OS初期設定

3.1 ファイル名拡張子の表示

  1. エクスプローラーを開く
  2. 表示 ＞ 表示を開く
  3. ファイル名拡張子を有効化

実行ファイルや設定ファイルの種類を誤認しないよう、拡張子を常に表示する

3.2 タイムゾーン設定

  1. Windows + Rを押し、timedate.cplを実行
  2. タイムゾーンの変更を選択
  3. (UTC+09:00) 大阪、札幌、東京を選択

3.3 Windows Updateの自動ダウンロードとインストール通知

計画したメンテナンスウィンドウで更新を実施する運用に合わせ、更新プログラムを自動ダウンロードし、インストールの前に通知する

  1. Windows + Rを押し、gpedit.mscを実行
  2. コンピューターの構成 ＞ 管理用テンプレート ＞ Windowsコンポーネント ＞ Windows Update ＞ エンド ユーザー エクスペリエンスの管理の順に開く
  3. 自動更新を構成するを開く
  4. 有効を選択
  5. 自動更新の構成へ3 - 自動ダウンロードしインストールを通知を指定して保存
⚠️ 注意

この設定では更新プログラムが自動適用されません。AWS Systems Manager Patch Manager、WSUS、SCCMなどで定期的に更新を適用する運用を必ず用意し、既知の脆弱性を残さないようにする

3.4 RDPセキュリティ設定

3.4.1 RDPセッション制限

  1. Windows + Rを押し、gpedit.mscを実行
  2. 管理用テンプレート ＞ Windowsコンポーネント ＞ リモート デスクトップ サービス ＞ リモート デスクトップ セッション ホスト ＞ 接続の順に開く
  3. 接続数を制限するを開き、接続数の上限を設けない場合は無効を選択
  4. 複数セッションが必要な場合のみ、リモート デスクトップ サービス ユーザーに対してリモート デスクトップ サービス セッションを1つに制限するを無効化

3.4.2 RDP暗号化レベル

RDPのネイティブ暗号化を利用する接続に対して、クライアントとサーバー間の暗号化レベルを高へ固定する

  1. Windows + Rを押し、gpedit.mscを実行
  2. コンピューターの構成 ＞ 管理用テンプレート ＞ Windowsコンポーネントの順に展開
  3. リモート デスクトップ サービス ＞ リモート デスクトップ セッション ホスト ＞ セキュリティの順に展開
  4. クライアント接続の暗号化レベルを設定するを開く
  5. 有効を選択し、暗号化レベルへ高を指定
  6. gpupdate /forceを実行
ℹ️ 情報

高はRDPのネイティブ暗号化へ128ビット暗号化を要求する設定です。TLSをセキュリティレイヤーとして使用する接続では、証明書とTLS設定を優先して設計します。FIPS準拠設定は互換性へ影響するため、準拠要件がある場合だけ別途検証する

出典：Microsoft公式: Remote Desktop Servicesポリシー

3.5 Windows Defender Firewallの無効化

本手順の対象環境では、通信制御をSecurity Groupなどの上位レイヤーへ集約し、OS側との二重管理による設定差分や疎通障害を避ける社内標準に基づいてWindows Defender Firewallを無効化する

  1. Windows + Rを押し、wf.mscを実行
  2. Windows Defender ファイアウォールのプロパティを開く
  3. ドメイン、プライベート、パブリックの各プロファイルでファイアウォールの状態を無効に変更
  4. 設定を保存
⚠️ 注意

Windows Defender Firewallの無効化は、すべての環境に適用する一般的なAWS推奨ではありません。AWSはOS側ファイアウォールを多層防御として利用することを推奨しています。本手順は、Security GroupとNetwork ACLによる通信制御、EDRによる検知・防御、変更承認が整備された対象環境に限って適用する

3.6 追加ボリュームの初期化

  1. Windows + Rを押し、diskmgmt.mscを実行
  2. 未初期化ディスクの容量とディスク番号を確認
  3. パーティションスタイルへGPTを選択
  4. 未割り当て領域から新しいシンプル ボリュームを選択
  5. ドライブ文字へ<VOLUME_DRIVE_LETTER>を割り当て
  6. ファイルシステムへNTFSを選択し、要件に合わせたボリュームラベルを設定
  7. クイックフォーマットを実行

4. AWS管理機能の設定

4.1 CloudWatch Agent導入

AWS Systems Manager Run Commandを使用して、Amazon CloudWatch Agentをインストールします。インストールだけではメトリクスやログは収集されないため、後続手順で設定ファイルを作成して適用する

  1. AWS Systems ManagerコンソールでRun Commandを開く
  2. コマンドドキュメントへAWS-ConfigureAWSPackageを選択
  3. ActionへInstall、NameへAmazonCloudWatchAgentを指定
  4. 対象インスタンスをタグまたはインスタンスIDで指定
  5. コマンドを実行
ℹ️ 情報

EC2インスタンスのIAMロールには、Systems Manager管理用のAmazonSSMManagedInstanceCoreと、メトリクス・ログ送信用のCloudWatchAgentServerPolicy相当の権限を付与します。設定ファイルにアクセスキーやシークレットアクセスキーを保存しない

出典：AWS公式: CloudWatch Agentのインストール

4.2 CloudWatch Agent設定ファイル作成

収集するWindowsイベントログ、パフォーマンスカウンター、収集間隔、CloudWatch Logsのロググループ名をJSON形式の設定ファイルへ定義する

分類設定例設計時の確認事項
WindowsイベントログSystem、Application収集するイベントレベル、保持期間、機密情報の有無
WindowsセキュリティログSecurity監査要件がある場合のみ追加し、ログ量と閲覧権限を確認
CPUProcessor(_Total)\% Processor Time収集間隔とアラームしきい値
メモリMemory\% Committed Bytes In UseOS標準メトリクスでは取得できないため、Agentで収集
ディスクLogicalDisk(*)\% Free Space一時ドライブや不要なボリュームを対象外にするか確認

4.2.1 Windows上のウィザードで作成

単体サーバーで設定内容を確認しながら作成する場合は、管理者権限のPowerShellから設定ウィザードを実行する

powershell
Set-Location "$Env:ProgramFiles\Amazon\AmazonCloudWatchAgent"
.\amazon-cloudwatch-agent-config-wizard.exe
  1. OSへWindows、実行環境へEC2を指定
  2. 収集間隔とパフォーマンスカウンターを選択
  3. 収集するWindowsイベントログ、イベントレベル、ロググループ名を指定
  4. ローカル利用の場合は、生成されたconfig.jsonを確認
  5. Parameter Storeで集中管理する場合は、保存確認へYesを選択し、パラメータ名とリージョンを指定

ローカルのconfig.jsonを使用する場合は、次のコマンドで設定を読み込み、Agentを起動する

powershell
& "$Env:ProgramFiles\Amazon\AmazonCloudWatchAgent\amazon-cloudwatch-agent-ctl.ps1" `
  -a fetch-config -m ec2 -s `
  -c "file:$Env:ProgramFiles\Amazon\AmazonCloudWatchAgent\config.json"

4.2.2 Parameter Storeへ保存

複数台へ同じ設定を配布する場合は、承認済みのJSONファイルをAWS Systems Manager Parameter Storeへ保存します。AWS管理ポリシーのCloudWatchAgentServerPolicyを利用する場合は、AmazonCloudWatch-WindowsServer2025のようにAmazonCloudWatch-で始まるパラメータ名を指定する

powershell
aws ssm put-parameter `
  --name "<CLOUDWATCH_AGENT_CONFIG_PARAMETER>" `
  --type "String" `
  --value file://cloudwatch-agent.json `
  --overwrite
⚠️ 注意

Parameter Storeへ設定を登録する作業者にはssm:PutParameter権限が必要です。EC2インスタンスにはssm:GetParameterだけを許可し、設定登録権限は付与しません。AmazonCloudWatch-以外のパラメータ名を使う場合は、対象パラメータに限定したssm:GetParameter権限をインスタンスロールへ追加します。Parameter Storeはアカウントおよびリージョン単位で管理されるため、適用先と同じリージョンへ登録する

出典：AWS公式: ウィザードによる設定ファイル作成

4.3 Run Commandによる設定適用

Parameter Storeに保存した設定を、AWS Systems Manager Run Commandから対象インスタンスへ適用する

  1. AWS Systems ManagerコンソールでRun Commandを開く
  2. コマンドドキュメントへAmazonCloudWatch-ManageAgentを選択
  3. Actionへconfigureを指定
  4. Modeへec2を指定
  5. Optional Configuration Sourceへssmを指定
  6. Optional Configuration Locationへ<CLOUDWATCH_AGENT_CONFIG_PARAMETER>を指定
  7. Optional Restartへyesを指定
  8. 対象インスタンスをタグまたはインスタンスIDで指定し、コマンドを実行
  9. コマンド出力が成功していることを確認し、CloudWatchのメトリクスとロググループへデータが到着していることを確認
ℹ️ 情報

共通設定をParameter Storeで管理すると、インスタンスへJSONファイルを個別配布せずに同じ設定を再適用できます。設定変更時はJSONをレビューし、Parameter Storeを更新してから対象タグ単位でRun Commandを実行する

5. 再起動を伴う最終作業

ここまでの再起動を伴わない設定と動作確認を完了してから、コンピューター名とWindows Updateを設定し、最後に再起動をまとめて実施する

5.1 コンピューター名設定

  1. Windows + Rを押し、sysdm.cplを実行
  2. コンピューター名タブ ＞ 変更を選択
  3. コンピューター名へ<HOSTNAME>を入力
  4. ドメイン参加が必要な場合は、名前解決と接続先Directory Serviceを確認して設定
  5. 再起動要求を確認し、この時点では再起動せず手順5.3まで保留

5.2 Windows Update

  1. Windows + Rを押し、ms-settings:windowsupdateを実行
  2. 更新プログラムのチェックを選択
  3. 検出された更新プログラムをダウンロードしてインストール
  4. 再起動要求を確認し、手順5.3へ進む

5.3 最終再起動と確認

  1. 業務影響、接続中の利用者、実行中ジョブがないことを確認
  2. 管理者権限のPowerShellでRestart-Computer -Forceを実行
  3. 再接続後、コンピューター名、RDP接続、監視、業務通信を確認
  4. Windows Updateを再確認し、更新プログラムが残っている場合はインストールと再起動を繰り返す
  5. 更新プログラムが検出されず、各動作確認が完了したことを記録
